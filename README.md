# 60sAPI Hub

基于 [60s API](https://github.com/vikiboss/60s) 的 AstrBot 资讯聚合与订阅插件，计划支持多站点配置、多接口组合、文字与图片生成，以及群聊和私聊白名单定时推送。

**最小插件入口、站点存储、后台站点管理、每日新闻、Bilibili 热搜、知乎热榜、抖音热搜和今日头条热榜获取预览，以及内容组合的持久化和后台组合预览已建立；管理员可在 AstrBot Dashboard 的插件视图中维护站点、组合站点栏目并主动预览。其他热榜、图文渲染、发送和调度尚未实现，当前不是可日常使用的插件，也没有发布版本。**

## 已实现

- 可被 AstrBot 发现、加载、停用、启用和重载的最小插件入口。
- 站点配置模型：名称、基础地址、启用状态、超时、可选 Bearer 凭据和 revision。
- HTTP(S)/内网/IPv6/反向代理前缀地址校验，以及误填 `/v2`、用户信息、查询串和 fragment 的明确拒绝。
- SQLite 站点增删改查、revision 冲突检测，以及凭据的保留、替换和清除。
- 插件停用/重载时关闭数据库连接，初始化失败时释放已创建资源。
- 嵌入 AstrBot Dashboard 的中文站点管理视图：列表、新增、编辑、启用/停用、超时和凭据维护、删除确认；加载、空列表、保存、校验失败、冲突和结果未确认状态；响应丢失时要求重新读取后再决定。
- 受 Dashboard 鉴权的插件 Web API：列表、新增、读取、编辑、删除；服务端校验、revision 冲突、凭据保留/替换/清除；停用后旧处理器拒绝读写，重载后不重复注册可写处理器。
- 站点管理页不会回显凭据原文，不使用 CDN、外部字体或独立 HTTP 服务，也不自行保存 Dashboard token。
- 每日新闻 `/v2/60s` 获取：按站点 ID 由服务端读取地址、启用状态、超时和凭据；异步 HTTP、响应大小限制、有限重试、超时、拒绝跨源重定向、关闭时等待自有请求，以及错误正文不回显凭据的客户端生命周期管理。
- 每日新闻内容快照：来源、接口、获取时间、上游内容日期、旧内容/缺失日期提示和有序新闻条目；合法空内容与结构错误分开处理。
- 后台“内容预览”：选择已启用站点和内容类型后主动获取；每日新闻显示内容日期和旧内容提示，Bilibili 热搜显示标题/链接，知乎热榜显示标题、摘要、热度文本和链接。普通获取优先使用未过期缓存，“刷新上游”强制请求；打开页面、切换类型、保存站点和启动插件不会自动请求上游。
- Bilibili 热搜 `/v2/bili`：返回 `data` 数组，只使用上游明确的标题和可选搜索链接；保留实际顺序和条数，不把列表序号当排名，不生成热度或更新时间。
- 知乎热榜 `/v2/zhihu`：返回 `data` 数组，使用标题、可选摘要、原始热度文本和可选安全链接；保留实际顺序和条数，不把列表序号当排名，不生成排名或更新时间，不自动请求封面图片。
- 抖音热搜 `/v2/douyin`：返回 `data` 数组，使用标题、原始整数热度值和可选安全搜索链接；保留实际顺序和条数，不换算热度单位，不把列表序号当排名，不生成或解释更新时间，不渲染封面。
- 今日头条热榜 `/v2/toutiao`：返回 `data` 数组，使用标题、原始整数热度值和可选安全链接；保留实际顺序和条数，不换算热度单位，不把列表序号当排名，不生成或解释更新时间，不渲染封面。
- 五种 endpoint 共用一个异步 HTTP 客户端和全局并发预算；每日新闻的日期语义与 Bilibili/知乎/抖音/今日头条的列表语义分别保留。
- 统一内容预览使用进程内有界缓存：默认 TTL 300 秒、最多 32 项、LRU 淘汰；普通获取命中缓存时不请求上游，页面另提供“刷新上游”强制刷新。缓存键包含站点、内容类型、固定空参数和站点 revision，不包含凭据。
- 内容组合使用同一 SQLite 持久化：一个组合引用一个站点，按数组顺序选择 1～5 个现有内容类型，每栏条数为空或 1～1000；组合预览只请求选中的 endpoint，按配置顺序返回并逐栏截取，单内容缓存保持完整。被组合引用的站点不能删除。

## 功能规划（尚未实现）

- 继续接入每日新闻、Bilibili 热搜、知乎热榜、抖音热搜、今日头条热榜之外的接口。
- 根据上游 JSON 自行组织文字、Markdown 和图片，支持多栏目与图片分页。
- 在 AstrBot 后台配置定时任务与发送。
- 每个任务独立填写完整 UMO 白名单，可混合群聊和私聊。
- 支持手动查询、定时推送、执行记录和失败处理。

## 项目状态

M1 基础集成和 M2 内容获取已验收，验证基线为 AstrBot v4.29.1 / Python 3.12.13；五个 endpoint、有界预览缓存、内容组合及后台预览通过基线验收，195 项自动化测试通过。M3 图文输出尚未开始；该阶段验收不代表 MVP 已完成、公开上游始终可用或插件已正式发布。后续功能通过短期分支开发与 PR 合并。

最小插件入口、站点存储、后台站点管理和内容预览已建立。站点配置可通过 AstrBot Dashboard 的“站点管理”页面或受鉴权的插件 Web API 新增、读取、编辑、启用/停用和删除，并持久化到插件数据目录的 SQLite。每日新闻、Bilibili 热搜、知乎热榜、抖音热搜和今日头条热榜预览按站点 ID 和内容类型获取上游 JSON，并解析为各自的内容快照；统一预览优先使用未过期缓存，可手动刷新。内容组合可持久化站点、栏目顺序和每栏条数，并按组合配置进行部分失败容忍的组合预览。其他热榜、图文渲染、白名单和调度尚未实现。

已在 AstrBot v4.29.1 / Python 3.12.13 的隔离源码环境验证加载、停用、启用和重载，以及真实 Dashboard 登录后的站点管理与内容预览页/API：数据库位于 `data/plugin_data/astrbot_plugin_60sapi_hub/sites.sqlite3`，停用后连接关闭，启用/重载保留数据且无重复实例；未登录请求被拒绝，停用后的旧处理器返回不可用，凭据不会回显。每日新闻、Bilibili 热搜、知乎热榜、抖音热搜和今日头条热榜完整链路使用本地模拟上游验证正常、空内容、HTML 文本、HTTP/业务/非 JSON/超时/大小限制/重定向、停用/重载和窄屏场景；统一预览另验证首次获取、缓存命中、强制刷新、配置 revision、禁用/删除、刷新失败保留旧缓存和在途关闭；内容组合另验证 SQLite v1→v2 迁移、CRUD/revision、引用站点删除拒绝、部分/全部失败、逐栏截断和重启持久化；知乎公开实例返回 30 条、抖音/今日头条公开实例各返回 50 条真实列表，Bilibili 公开实例本次请求返回 HTTP 500，未把演示站点配置为默认站点。真实消息平台、其他热榜和真实公开实例浏览器全链路未验证。验证方法与兼容范围见[开发手册](docs/development.md#astrbot-兼容性基线)。

程序版本唯一来源为 [metadata.yaml](metadata.yaml)，当前为 `v0.1.0-dev.1`。运行依赖见 [requirements.txt](requirements.txt)，当前为 `aiosqlite`（异步 SQLite）和 `httpx`（异步 HTTP）；AstrBot 本体由宿主提供，不列为插件依赖。

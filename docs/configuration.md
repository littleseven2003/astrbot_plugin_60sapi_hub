# 配置说明

站点配置、后台管理、五种内容预览、内容组合、图文输出及任务配置/UMO 白名单已实现；投递核心仅通过假发送器验证，真实平台发送、后台投递入口、其他热榜和导入等功能尚未接入。

### 后台站点管理

在 AstrBot Dashboard 打开插件视图“站点管理”，可以查看站点列表、新增站点、编辑名称/基础地址/启用状态/超时/凭据，以及确认后删除站点。页面会显示加载、空列表、保存、校验失败、revision 冲突和结果未确认状态。字段校验失败会保留已填写的表单内容并允许修正；网络中断、超时或响应丢失时，服务器可能已经保存，页面会锁定写按钮，要求先重新读取最新列表，不能直接重复提交。

后台通过宿主提供的插件 bridge 调用受 Dashboard 鉴权的插件 Web API，不另建 HTTP 服务、登录系统或 token 存储。服务端对每次请求重新校验输入；编辑和删除要求携带期望 revision，冲突时返回明确错误且不自动覆盖，页面重新读取最新数据后由管理员决定是否再次编辑。

凭据编辑默认选择“保留原凭据”，另有“设置新凭据”和“清除凭据”。密码输入框不会预填，保存后页面只显示是否已设置，不显示原文。站点保存只做字段和地址格式校验，不发起连通性测试；内容预览是页面中单独的主动操作。

## API 站点

配置名称、基础地址、启用状态、可选 Bearer 凭据、超时。基础地址约定不含 /v2，可包含反向代理前缀；例如 https://api.example.com/news。

后台会提示误填 /v2，避免重复拼接；保留反代前缀。仅允许 HTTP(S)，不在基础地址中包含用户名密码、查询串或 fragment。

管理员可配置明确的内网/Docker 站点。endpoint 使用受控相对路径，普通聊天不能指定任意 URL；跨源重定向不得转发凭据。凭据在返回结果与日志中脱敏。

### 已实现的站点字段

站点由 `core/sites.py` 的站点服务和 `core/site_store.py` 的 SQLite 存储管理。公开站点结构只返回是否已设置凭据，不返回凭据原文。

| 字段 | 规则 |
|---|---|
| id | 新增时生成的稳定 ID，不因改名改变 |
| name | 去除首尾空白后 1～80 个字符，不能包含换行或控制字符 |
| base_url | 去除首尾空白后 1～2048 个字符，规则见下文 |
| enabled | 布尔值，新增默认关闭 |
| timeout_seconds | 1～120 秒，默认 10 秒；拒绝布尔值、NaN 和 Infinity |
| bearer_token | 可选，最长 4096 个可见 ASCII 字符；不能包含空白；只返回 `has_bearer_token` |
| revision | 从 1 开始，每次成功编辑加 1 |
| created_at / updated_at | UTC ISO 8601 时间字符串 |

地址规则：

- 仅允许 `http` 或 `https`，必须包含主机名；端口如填写则必须在 1～65535 之间。
- 支持 `localhost`、内网 IPv4、方括号 IPv6、Docker/内网单标签主机名和反向代理路径前缀。
- 拒绝用户名、密码、查询串和 fragment；即使只有一个 `?` 或 `#` 也拒绝。
- 拒绝反斜杠、空白路径和未编码空格；IPv6 不支持 zone ID；主机名按 ASCII 语法检查，国际化域名需使用 punycode。
- 拒绝地址内部的 CR、LF、Tab、NUL 等控制字符；首尾空白仍会按上文规范化。
- 只去除首尾空白和路径末尾的斜杠，保留路径前缀；不做 DNS 查询，也不以公共网络可达性决定是否有效。
- 路径以 `/v2` 结尾时明确报错，避免请求时重复拼接；`/api/v2/news` 等不以 `/v2` 结尾的路径允许。

### 凭据编辑语义

编辑站点时使用 `credential_action` 区分三种操作：

| 操作 | 行为 |
|---|---|
| `keep` | 保留原值，编辑时的默认值；空白表单不会清除原凭据 |
| `set` | 设置新值，必须提供非空凭据 |
| `clear` | 清除凭据，不提交新值 |

凭据原文保存在插件数据目录的 SQLite 中，不进入公开站点结构、日志、错误消息或对象调试输出。数据库文件应按敏感数据保护，不提交或分享。

## 内容预览

后台当前支持五种内容类型，均只请求已保存站点：

| 内容类型 | endpoint | 真实字段 |
|---|---|---|
| 每日新闻 | `/v2/60s` | 内容日期、有序新闻条目、可选微语/来源链接 |
| Bilibili 热搜 | `/v2/bili` | 有序标题和可选搜索链接；没有排名、热度或更新时间字段 |
| 知乎热榜 | `/v2/zhihu` | 有序标题、可选摘要、原始热度文本和可选链接；没有排名或更新时间字段 |
| 抖音热搜 | `/v2/douyin` | 有序标题、原始整数热度值和可选搜索链接；没有排名或更新时间字段 |
| 今日头条热榜 | `/v2/toutiao` | 有序标题、原始整数热度值和可选链接；没有排名、摘要、标签或更新时间字段 |

页面只提交站点 ID 和固定内容类型；服务端从站点存储读取地址、启用状态、超时和凭据。未知内容类型由后端直接拒绝，不会据此拼接或请求任意 URL。站点不存在或未启用会被拒绝。请求不会自动发生在打开页面、切换内容类型、保存站点或启动插件时；必须由管理员主动点击“获取内容”。

### 每日新闻

请求地址由站点 `base_url` 与 `/v2/60s` 拼接，保留反向代理路径前缀；不额外传 `date` 或 `encoding` 参数，JSON 为默认响应。地址支持内网、Docker 主机名和方括号 IPv6，不以公共网络可达性作为配置条件。

结果快照包含来源站点、内容类型、接口路径、获取时间、上游内容日期、警告和按上游顺序排列的新闻条目。内容日期可能缺失或格式无法识别，此时显示“未知”；早于当前中国日期的内容会明确提示旧内容，但保留来源日期，不用抓取日期覆盖。`data.news: []` 是合法空内容，与 JSON 结构错误或网络失败分开显示。

### Bilibili 热搜

请求地址为站点 `base_url` 与 `/v2/bili` 拼接。该接口当前返回 `data` 数组，条目由 60s API 映射为 `title` 和 `link`；本插件只使用这两个字段，数组顺序即上游返回顺序，实际条数按列表长度显示。

当前响应没有排名、热度或更新时间字段。页面不显示这些指标，也不把列表序号解释为上游排名；获取时间是本插件的请求时间，不是上游更新时间。`data: []` 是合法空列表。标题缺失或不是非空字符串视为结构错误；链接缺失、不是字符串或不是安全的 HTTP(S) 地址时只忽略链接，不会让整次预览失败或执行上游 HTML。

### 知乎热榜

请求地址为站点 `base_url` 与 `/v2/zhihu` 拼接。当前接口返回 `data` 数组，条目使用 `title`、可选 `detail`、可选 `hot_value_desc` 和可选安全 `link`。

`hot_value_desc` 是类似“1670 万热度”的原始文本，插件原样展示，不换算成数值。`detail` 是摘要文本，可为空。`created`/`created_at` 是话题创建时间，不是更新时间；接口没有排名字段。页面不使用数组序号冒充排名，也不显示“更新时间”。`cover` 图片地址不渲染，避免自动请求远程图片。`data: []` 是合法空列表；标题缺失是非空字符串以外的结构错误。

### 抖音热搜

请求地址为站点 `base_url` 与 `/v2/douyin` 拼接。当前只接入文档中的默认实时热搜榜，不提供榜单变体选择。接口返回 `data` 数组，条目使用 `title`、可选原始整数 `hot_value` 和可选安全 `link`。

热度值按上游整数原样展示，例如“热度：12189774”，不擅自换算成“万”或其他单位。接口没有排名字段；数组顺序即上游返回顺序，序号不冒充排名。`event_time/event_time_at`、`active_time/active_time_at` 等时间字段虽存在，但其单位/语义当前未作为更新时间使用，页面不展示；获取时间也不冒充更新时间。`cover` 不渲染，避免自动请求远程图片。`data: []` 是合法空列表；标题缺失或不是非空字符串是结构错误。

### 今日头条热榜

请求地址为站点 `base_url` 与 `/v2/toutiao` 拼接。当前只接入固定默认热榜，无查询参数或榜单变体。接口返回 `data` 数组，条目使用 `title`、可选原始整数 `hot_value` 和可选安全 `link`。

热度值按上游整数原样展示，例如“热度：112229604”，不换算单位。接口没有排名字段；数组顺序即上游返回顺序，页面不把序号当排名。没有摘要、标签、更新时间或独立时间字段；获取时间不冒充更新时间。`cover` 不渲染，避免自动请求远程图片。`data: []` 是合法空列表；标题缺失或不是非空字符串是结构错误。

### 共用获取能力

五种内容共用一个异步 HTTP 客户端、连接池和全局并发上限，不按 endpoint 分别创建客户端。请求使用站点超时作为整体上限，连接超时不超过 5 秒；响应体最多读取 2 MiB；最多尝试 2 次（仅重试网络错误及 408/429/502/503/504），且所有重试都受整体超时约束。重定向一律不跟随，凭据不会转发到重定向目标。共享客户端在插件启用时创建；停用或重载时先拒绝新请求，取消并等待本客户端拥有的在途、排队和重试等待任务，再关闭连接。外部调用取消会继续向调用方传播。

### 缓存与刷新

统一预览使用进程内有界缓存，不新增数据库表、Redis、磁盘缓存或后台刷新：

- 仅缓存成功解析后的不可变内容快照，包括合法空列表；错误不缓存。
- 默认 TTL 300 秒，最多 32 项；过期项读取时清理，容量满时按 LRU 淘汰。TTL 从成功完成获取时开始，使用可注入的单调时钟判断。
- 缓存键包含站点 ID、内容类型/固定 endpoint、明确的空参数和站点 revision；Bearer 令牌不在键、响应、日志或 repr 中。
- 每次读取前重新检查站点存在且已启用。名称、地址、凭据等配置修改会增加 revision，旧版本快照不能被新版本复用；站点删除或停用后不会返回旧缓存。
- 普通“获取内容”有效缓存命中时不请求上游；“刷新上游”绕过已完成缓存，但可复用同键当前在途的获取，不能直接返回旧缓存。同键并发获取合并为一次上游操作。
- 单个等待者取消不影响其他等待者；最后一个等待者取消才取消共享获取。等待有上限（当前 130 秒），不会无限等待。
- 共享获取一旦决定取消，立即从同键等待记录中移除；新的同键请求发起新的获取，不会加入正在取消的旧任务。旧任务仍由缓存生命周期集合管理，`close()` 会等待其清理完成；旧任务不能覆盖新缓存或删除新请求的在途记录。
- 刷新失败不会写入错误或覆盖旧成功缓存；页面明确报错。后续普通获取仍可使用尚未过期的上一份成功缓存。
- 每日新闻若跨中国日期，缓存失效并重新获取，避免展示昨日计算的“非旧内容”状态；快照原 `fetched_at`、内容日期和上游指标不会被缓存命中改写。
- 停用或重载时缓存层先拒绝新操作，取消并等待自有在途任务，清空缓存，再关闭共享 HTTP 客户端；不会留下后台任务。
- 统一预览请求可选 `force_refresh`，缺省 `false`，必须是严格布尔值；字符串、数字、`null` 等返回 400 且不触发上游。
- 统一预览响应额外返回 `cache.hit`、`cache.expires_at`（UTC ISO 8601）和 `cache.ttl_seconds`。`cache.hit=true` 表示未请求上游；`force_refresh` 成功和首次未命中均为 `false`。缓存元信息不写入领域快照，不改变 `fetched_at`。旧每日新闻独立 API 不改变原有响应结构，也不强制使用缓存。

上游 HTTP 错误只显示程序生成的安全提示和数字状态码；HTTP 200 业务错误只显示业务 code。上游错误正文不会进入后台响应或日志，避免其回显 Bearer 凭据或其他敏感文本。每日新闻、Bilibili 热搜、知乎热榜、抖音热搜和今日头条热榜各自实际使用的站点凭据隔离发送。

## 内容组合

一个组合选择一个已保存站点和 1～5 个现有内容类型；栏目数组顺序就是展示顺序，不维护另一份排序值。每个栏目包含固定内容类型、`params` 和 `limit`：当前接口没有用户参数，`params` 只接受空对象；`limit=null` 表示全部，正整数表示每栏最多展示 1～1000 条。拒绝布尔值、零、负数、小数、数字字符串、未知类型、重复类型、非空参数和任意 URL。

组合保存时校验站点存在；允许引用已停用站点，但组合预览返回明确的 409 `site_disabled`，不请求上游。组合使用稳定 ID、名称、站点 ID、栏目数组、revision、创建/修改时间。

### 后台 API

| 方法与路径 | 用途 |
|---|---|
| `GET /<插件名>/profiles` | 列出组合，包含引用站点名称和启用状态 |
| `POST /<插件名>/profiles` | 新增组合 |
| `GET /<插件名>/profiles/<id>` | 读取单个组合 |
| `POST /<插件名>/profiles/<id>/update` | 按期望 revision 编辑组合 |
| `POST /<插件名>/profiles/<id>/delete` | 按期望 revision 删除组合 |
| `POST /<插件名>/profiles/<id>/preview` | 获取或刷新组合预览，并返回短期图片快照标识 |
| `POST /<插件名>/profiles/<id>/image` | 用已接受快照生成分页 PNG |

编辑和删除使用与站点一致的 revision 冲突保护。删除被任意组合引用的站点返回 409 `site_referenced` 和引用组合名称，不静默级联删除组合；数据库外键同时使用 `ON DELETE RESTRICT`。

组合预览只接受已保存组合 ID，由服务端读取组合和站点，不接受客户端任意 URL。它按配置顺序逐栏调用现有统一预览服务，复用共享 HTTP 客户端、全局并发预算和内容缓存；只请求选中的内容类型，按栏目 `limit` 截取返回条目，不修改缓存中的完整不可变快照。每栏保留来源、`fetched_at`、缓存元信息、条数和每日新闻日期语义。

预览请求支持严格布尔 `force_refresh`。响应按栏目返回 `status`：
- `complete`：全部栏目成功，合法空列表仍算成功。
- `partial`：至少一栏成功、至少一栏失败；成功栏目保留，失败栏目返回安全 `code/message`。
- `failed`：全部栏目失败，HTTP 502，绝不显示成空内容成功。

失败栏目不会暴露堆栈、凭据或原始上游错误正文；HTTP 状态和业务 code 只以数字形式出现。

成功或部分成功的组合预览响应增加独立 `outputs`：

```json
"outputs": {
  "text": "组合：...",
  "markdown": "# ..."
}
```

- 两种格式由同一份预览数据纯函数生成，共享组合版本、栏目顺序、截取后的条目、来源、`fetched_at`、限制和缓存/日期信息；不会再次请求上游，也不写入领域快照或缓存。
- 文字包含组合名、站点、完整/部分成功状态、栏目、获取时间、展示条数和限制、每日新闻日期/提示、真实标题/摘要/热度/链接；空栏目明确显示空。
- Markdown 只由渲染器生成结构；上游组合名、站点名、标题、摘要、热度文本均做 HTML 和 Markdown 转义，换行折叠，不能插入标题、链接、图片或 HTML。链接只使用已有校验后的 HTTP(S) 地址，并对括号/空格等百分号编码；无法安全生成时降级为文本。封面不输出。
- 全部失败响应没有 `outputs`；页面清除旧输出并禁用复制/下载。
- 后台提供纯文字/Markdown 源码切换、复制和 UTF-8 下载。文件名固定为 `60sapi-profile-<组合 ID>.txt` 或 `.md`，不拼接组合名称。格式切换、复制和下载只使用当前已接受的响应，不访问上游。
- 复制开始时保存格式、文本、输出 epoch 和操作序号；完成提示或降级选区前重新检查这些身份。格式切换、预览刷新/失效、组合切换、编辑、下载或更新的一次复制都会使旧回调失效，旧回调不能修改提示、焦点、选区或按钮状态，也不使用全局锁阻塞预览。
- 预览成功/部分成功时，服务端额外保存短期图片快照，并返回不透明 `image_snapshot`：
  ```json
  "image_snapshot": {"id": "opaque-token", "expires_at": "ISO-8601"}
  ```
  快照只保存该次预览已经验证、截取的组合名、站点名、状态、计数和 `sections`；不保存输出文本、HTML、任意前端 URL、文件路径或原始上游正文。
- 图片生成请求只接受 `{"snapshot_id": "opaque-token"}`，组合 ID 来自已保存路由；服务端根据快照渲染，不接受前端传入内容、页面尺寸、文件路径或图片 URL。
- 图片快照默认有效期 300 秒、最多 32 个、总大小 8 MiB，单快照最多 2 MiB；超出单快照限制时预览仍成功返回文字/Markdown，但不返回 `image_snapshot`，页面禁用图片生成。容量满时按未使用时间 evict；访问过期/淘汰快照返回 410 `snapshot_expired`，插件关闭时清空。
- 图片接口沿用 Dashboard 鉴权；快照保存请求用户，生成时校验归属（不匹配 403 `forbidden`）。同时重新读取组合和站点并比较预览时的 `profile_revision`、`site_id`、`site_revision` 和启用状态；组合/站点修改、删除或停用返回 409 `snapshot_stale`，提示重新预览，不自动取新缓存或请求上游。
- `POST /profiles/<id>/image` 成功返回 `page_count`、固定宽高和逐页 `index`、`width`、`height`、`sha256`、`png_base64`；图片只从快照生成。单页 900×1200，最多 6 页，总像素 8,000,000，单页 PNG 4 MiB，全部 PNG 12 MiB，base64 JSON 响应最多 16 MiB；单个文本字段超过 200,000 字符或排版行数超过 360 行会提前终止。超限返回 422 `image_limit_exceeded`，不静默截断，文字/Markdown 仍可用。
- 渲染在受限线程池执行，最多 2 个实际执行、4 个排队（准入 6 个）；20 秒总超时覆盖排队和执行。超时或取消后后台线程仍占用名额直至真正结束，避免连续超时造成线程池无界积压；准入清理完成前不会提前移交名额，清理期间取消仍会归还且不会重复释放；超时返回 504 `image_timeout`，插件关闭会拒绝排队请求并关闭线程池。字体缺失返回 503 `font_unavailable`；渲染异常返回 422 `image_render_failed`，不会影响已返回的文字/Markdown。
- 图片是固定中文样式，由 Pillow 直接绘制，不使用 HTML 模板；上游文本按普通文本绘制并折叠控制字符，不加载封面、远程字体、CDN、内容链接或公共图片渲染服务。页面通过 data URL 展示生成结果，逐页下载文件名固定为 `60sapi-profile-<组合 ID>-page-<页码>.png`，不暴露绝对路径。
- 图片输出依赖 Pillow 和宿主 CJK 字体；字体按系统候选路径发现（macOS 验证使用 Hiragino Sans GB，Linux 支持 Noto Sans CJK/WenQuanYi 等），也可用 `ASTRBOT_60SAPI_FONT` 指向字体文件。字体随宿主提供，不随插件分发。自动发现和显式字体都会验证常见中文字符的实际字形；只有可加载但中文缺字的字体（例如 Arial）不会被采用，无法找到合格字体时明确失败。
- 剪贴板不可用时页面选中文本并提示手动复制；只有 `writeText` 实际成功后才提示复制成功。隔离宿主 iframe 会拒绝自动剪贴板权限，实际验证覆盖该降级路径；成功回调分支使用可控 Promise 验证，不描述为真实系统剪贴板写入成功。

组合列表成功刷新后，前端比较当前组合的 revision、名称、站点和栏目签名；变化或删除时清除当前预览，不自动获取。组合编辑/删除成功或冲突时也立即使旧预览失效。预览响应必须同时匹配当前请求令牌、当前组合 ID 和当前已知 revision，旧 revision 响应被丢弃；旧请求的 finally 不得清除新请求的忙状态。

## 推送任务

本轮只实现任务配置和 UMO 白名单，不发送消息、不启用任务、不调度、不请求上游。任务固定为未启用；后端没有启用、调度或发送接口。

任务字段：稳定 ID、名称（沿用站点名称规则，最多 80 字符）、一个已保存内容组合 ID、输出方式（`text`、`markdown`、`image`）、独立 UMO 白名单、revision、创建/修改时间。允许空白名单；允许组合引用的站点已停用；必须引用实际存在的内容组合。配置可保存不代表可投递。

| 方法与路径 | 用途 |
|---|---|
| `GET /<插件名>/tasks` | 列出任务及组合名称、站点启用状态、目标数量 |
| `POST /<插件名>/tasks` | 新增任务 |
| `GET /<插件名>/tasks/<id>` | 读取任务 |
| `POST /<插件名>/tasks/<id>/update` | 按 expected_revision 编辑任务 |
| `POST /<插件名>/tasks/<id>/delete` | 按 expected_revision 删除任务 |

请求中出现 `enabled`、`schedule` 或 `next_run` 返回 400 `unsupported_enable_request`，不会写入。`expected_revision` 缺失、null、布尔值、零、负数、小数或字符串返回 400 `validation_error`（字段 `expected_revision`），不会写入；合法但过期的整数 revision 返回 409 `revision_conflict`。任务响应固定返回 `enabled=false`、`can_send=false`。删除被任务引用的内容组合返回 409 `profile_referenced` 和任务名称；数据库外键同时使用 `ON DELETE RESTRICT`。删除任务不会删除组合或站点。

## 推送白名单

每项一个完整 UMO：`平台适配器实例ID:消息类型:完整会话ID`。只在**前两个**冒号处分割，会话 ID 内部的冒号保留；只对整条输入去首尾空白，平台字段、消息类型和会话 ID 内部内容不做 trim。平台字段含任何空白直接拒绝；会话 ID 的前导/内部空白和内部冒号原样保留。按规范化后的完整字符串精确去重并保留首次出现顺序，不改大小写或改写内部内容。合法保存值严格等于整条输入 strip 后的值。

- 平台字段是 AstrBot 平台适配器实例 ID（例如 `aiocqhttp`、`qq_official`），不是固定平台类型名；不能包含冒号、感叹号或空白，最多 128 字符。
- 消息类型只接受 `GroupMessage` 和 `FriendMessage`；`OtherMessage` 等拒绝。
- 会话 ID 不能为空，最多 384 字符；完整 UMO 最多 512 字符。
- 每任务最多 20 个输入项；空白名单合法。拒绝裸群号、裸 UID、缺字段、空字段、非法类型、控制字符、平台 ID 含冒号/感叹号、超出长度或数量限制。
- 支持群聊和私聊混合；格式合法但平台适配器当前未连接的配置可以保存，保存成功不代表已确认可发送。
- `unique_session` 下的群成员隔离会话 ID 原样保留，不擅自改成群级目标；如需群级目标，应按 AstrBot `/sid` 的提示核对并手工填写，不自动猜测。
- 后台提示使用对应会话的 `/sid` 获取完整 UMO，不把 UID 当 UMO；一行一个，后端统一接收字符串数组。名单按任务独立保存，不导入、继承或修改 AstrBot 全局入站白名单，不增加绑定指令。

## 手动测试投递（后台）

管理员可在任务卡片点击“测试投递”。确认页读取最新任务、组合、站点 revision 和全部目标：

- 展示任务、组合、站点、输出方式、任务/组合/站点 revision。
- 展示每个完整 UMO、平台实例、群聊/私聊实际目标；成员隔离明确标注最终路由到群。
- 无效/不支持目标不静默移除，确认按钮不可用；空名单明确不可投递。
- 确认后按当前配置获取**最新内容**，不复用页面旧预览；请求不携带 UMO、正文、URL 或文件路径。
- 提交携带稳定 execution_id 和三项 expected revision；投递核心在读取配置后再校验，变化返回 409，必须重新审阅。
- 每次明确操作生成新标识；响应丢失只查询该标识，不自动重新 POST。未知执行不自动重发。
- 执行记录查询无副作用；列表默认 20、最多 50，支持 offset/task_id，按创建时间/id 稳定倒序；删除任务后历史保留。
- 公开投影不返回 owner_token、凭据、路径或堆栈；必要 UMO 仅后台鉴权可见。
- 浏览器 bridge 的 GET 分页参数必须通过 `apiGet(endpoint, params)` 传递，不拼查询串；后台默认 20、最大 50，可“加载更多”。
- 一次确认对应一个稳定 execution_id。提交后 running/unknown/超时/响应丢失只查询该标识；不重新启用旧确认按钮、不生成新 ID 重发。revision 冲突作废确认，必须重新审阅。
- 历史详情为只读模式，不沿用旧 preview 或可提交按钮。弹窗维护统一查询上下文：新提交创建 execution_id 时即绑定，历史/未确认/新提交切换时更新或清除，查询按钮始终使用当前显示的执行标识。查询历史 A 不会清除待确认 B；只有标识匹配的结果才能清除对应尝试。
- iframe 禁用 localStorage 时，当前页内存仍保存未确认标识并可查询；刷新后无内存恢复，只能从执行记录人工核对，不能自动重发或放宽 sandbox。
- 预览、提交、详情查询和弹窗切换均做请求归属检查；迟到响应不能覆盖新弹窗、清除其他执行标识或解除新请求忙状态。
- 启动、保存、预览、查询、停用和重载零发送；只有手动提交进入投递服务。任务 enabled 仍不可修改。



本轮支持 **仅 AstrBot v4.29.1 的 aiocqhttp/OneBot v11 适配器**，其他适配器明确返回 `sender_not_supported`，不声称全平台兼容。

- 按已保存完整 UMO 中的平台实例 ID 精确调用 `Context.get_platform_inst()`；实例 ID 可以是 `demo_qq_01` 等任意配置值，不使用平台类型名代替。
- 通过真实 `Context.send_message()`、`MessageSession`、`MessageChain` 和 aiocqhttp `send_by_session()` 路由；群成员隔离会话按宿主规则处理，不自行统一截取或改写 UMO。
- 普通群聊会话必须是纯 ASCII 数字 group_id；成员隔离会话必须是 AstrBot aiocqhttp 入站构造的 `sender_id_group_id`，即恰好一个下划线且两段均为完整 ASCII 数字。私聊必须是纯 ASCII 数字，不含下划线或冒号。空前缀、非数字字段、多余下划线、混入冒号等无法确认的格式在调用宿主前拒绝，不通过“取最后一段”把畸形输入变成另一目标。
- text 使用 `Plain`；Markdown 作为普通文本源码发送，不宣称原生富文本；image 只接受有效 PNG bytes（签名、Pillow 校验、8 MiB 上限），用 `Image.fromBytes`/base64 内存传递，不创建公开 URL、不读文件路径、不请求网络。
- 未找到实例、非 aiocqhttp、非法 UMO/目标/载荷在外部调用前返回 FAILED；已进入 `Context.send_message` 后的异常或无法确定结果返回 UNKNOWN；`CancelledError` 继续传播；不自动重试。
- 成功表示真实宿主路由方法正常完成并调用了支持的 aiocqhttp 发送路径，不保证平台已读、绝对送达或平台 API 回执成功。异常正文/平台响应/凭据不落库、不打印 UMO/正文/PNG。
- 插件启动不装配该发送器；没有后台发送按钮、公开投递 API、聊天命令、启用或调度。
- 适配层验证使用真实 AstrBot v4.29.1 源码、真实 Context/aiocqhttp 路由/消息转换，最终机器人网络边界替换为隔离假机器人；未连接真实平台。

## 投递核心（内部，无后台入口）

本轮提供可独立测试的投递服务和执行记录，不注册后台发送按钮或公开 Web API，也不在插件启动时装配真实发送器。调用方只能提供已保存任务 ID 和执行标识；组合、输出方式、UMO、正文和图片均从已保存任务和现有预览生成，不能由调用方传入 URL、正文、UMO 或文件路径。

- 空名单在内容获取/渲染前结束，发送器调用零次。
- 一次执行只准备一份内容；文字/Markdown 为一个逻辑消息，图片按现有分页顺序逐页处理。
- 站点不存在/停用、组合不存在、全部栏目失败或图片生成失败时不调用发送器；本轮没有自动降级。
- 部分栏目失败沿用带失败提示的结果，缺失栏目记录在执行中；不自动改成全部成功。
- 服务的并发/等待准入在读取任务和组合之前执行；满额明确拒绝，不把积压移到读锁之后。执行总数不超过并发+等待上限的上界。
- 发送前先落库目标和页的 `sending` 状态；记录写入后、外部调用前再执行最终配置/生命周期校验，之后不再写入。外部发送不在数据库事务或存储锁内。
- 只有发送器明确 `success` 才记成功。明确 `failed` 记失败；普通异常、超时和取消保守记 `unknown`。
- 某目标出现失败/unknown 后停止该目标剩余页；其他目标继续。成功、失败、unknown、跳过分别记录，不把部分成功汇总成全部成功。
- 每次发送前重新核对任务、组合、站点 revision、目标仍存在且站点启用；变化后停止尚未开始的投递，不加入新目标，不替换内容。已进入外部调用的结果按实际/unknown 记录。
- 发送成功后写库失败不能变成安全重试；重复执行标识只返回已有状态，不自动重试、不自动恢复、不重启补发。超时返回已有记录前也校验任务归属，其他任务的记录不会被返回或修改。
- 正常 success、no_targets 及没有错误的页/目标保持 `error_code=NULL`；非法发送器错误文本统一归一化为受控内部码。每个执行记录带创建者 owner token；取消/超时/关闭时只有实际创建该记录的工作者能将其标记为 incomplete，重复查询者、创建竞争失败者和其他任务不得修改原执行。
- 执行记录保留任务/组合/站点快照 revision、输出格式、内容哈希、时间、目标和页，以及创建者 owner token；不保存完整新闻正文或 PNG。删除任务不级联删除历史投递记录。
- 关闭/取消及重开数据库时：尚未进入发送的 `pending` 页/目标终态为 `skipped`（原因 `never_started`）；已落库为 `sending`、可能已进入外部调用的页/目标才归 `unknown`；已知成功/失败保持原状态，执行按页汇总为 stopped/unknown/partial/failed。目标有成功页但剩余页 skipped 时目标为 partial，完全未投递才是 skipped。不补发。

默认上限：最多 20 个目标、6 个图片页、2 个并发执行、4 个等待执行、单次执行总截止 60 秒（覆盖准入、排队、准备和发送）、单次发送器调用 15 秒。等待数为 0 表示不排队，但空闲执行槽位仍可使用；执行槽位全满时立即返回容量错误。执行槽位必须 ≥1、等待数必须 ≥0；总执行超时和发送器超时必须为正的有限数值，拒绝 NaN、Infinity 和数值溢出，非法配置明确拒绝。服务层还会拒绝超过任务/图片既有上限的配置。

## 失败策略

- 部分栏目失败：发送可用栏目或跳过整次，并留下记录；本轮没有发送实现。
- 图片生成失败：按设置跳过或降级文字。
- 今日新闻未更新：跳过，或在截止时间前重试。
- 发送结果未知：明确标记，不盲目自动重发。
- 成功目标/页不因其他目标失败而重复发送。

## 数据与升级

站点、内容组合和推送任务保存在同一个数据库 `<ASTRBOT_ROOT>/data/plugin_data/astrbot_plugin_60sapi_hub/sites.sqlite3`；目录由宿主 `StarTools.get_data_dir()` 获取。schema 版本为 5：`sites`、`content_profiles`、`content_profile_items`、`push_tasks`、`push_task_umos`、`delivery_executions`、`delivery_targets` 和 `delivery_pages`。首次建库直接创建八张表；旧 v1/v2/v3/v4 数据库在同一事务中补齐组合/任务/投递表并提升 `user_version=5`，失败回滚，保留原站点、凭据、组合、栏目顺序、条数和 revision。

任务、投递记录与站点/组合共用同一个 `SiteStore` 连接、锁和事务，不另建 JSON 配置或复制到 `_conf_schema.json`。更新/删除任务按 expected_revision，冲突不覆盖；删除组合在事务中检查任务引用并由外键兜底；删除任务不级联删除组合。写入失败回滚，取消后下一次正常操作不受影响。

运行依赖 `aiosqlite`、`httpx` 和 `Pillow` 声明在 [requirements.txt](../requirements.txt)，不依赖宿主碰巧安装的版本，也不安装 AstrBot 本体。内容快照仍只在进程内缓存；任务配置和 UMO 持久化，执行/发送状态尚未实现。

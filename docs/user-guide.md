# 使用手册

**当前为开发源码版 `v0.1.0-dev.1`：没有正式发布版本、没有 git tag，只能从仓库源码安装。** 本手册说明如何从仓库源码安装到 AstrBot、配置自己的 60s API 站点、预览与组合内容、按任务白名单手动测试投递，以及启用计划。

实际验证的宿主版本是 AstrBot v4.29.1（Python 3.12.13 与 3.13.13 实测通过）；其他宿主版本未验证，本手册不声明最低兼容版本。真实账号的群聊/私聊发送与真实平台定时投递均尚未验证，后文逐项标注。项目不提供公共 60s API 站点；你可以自行搭建或部署，也可以使用你有权访问的现有 60s API 站点。

## 运行条件

- 宿主 AstrBot v4.29.1：实际验证版本；其他版本未验证，不声明最低兼容版本。
- 一个你有权访问的 60s API 站点：可自行搭建或部署，也可使用现有的自建或团队站点（需确认你有权访问并允许该用途）。插件只保存站点地址、超时和可选凭据，不内置公共站点，也不代理第三方服务。
- 已连接的消息平台适配器：只在“测试投递”和定时投递时需要；配置站点、预览内容和保存任务不需要平台在线。当前发送适配只覆盖 AstrBot v4.29.1 的 aiocqhttp/OneBot v11。
- Python 依赖：`aiosqlite>=0.21,<1`、`httpx>=0.27,<1`、`Pillow>=10,<15`、`croniter>=6.2.4,<7`，声明在仓库根部 `requirements.txt`，用 AstrBot 所在环境的解释器安装。AstrBot 本体由宿主提供，不由本插件安装。
- 图片输出需要宿主环境具备可用的中文字体，见下文“中文字体”。

## 安装、更新与卸载（开发源码）

以下步骤面向仓库源码安装。插件目录与数据目录是两处独立位置：更新和卸载默认只影响插件目录，数据目录保留。

文中出现的 `<ASTRBOT_ROOT>` 是**占位符**，代表 AstrBot 根目录（包含 `data/` 的那一层）。执行命令前请替换为你的实际绝对路径；不要把 `<...>` 原样粘进终端，命令行会把尖括号当成输入重定向。

### 安装

1. 把仓库内容复制到安装目录 `<ASTRBOT_ROOT>/data/plugins/astrbot_plugin_60sapi_hub`，推荐直接使用真实目录副本（逐目录复制或打包解压）。
   - 例如 AstrBot 根目录是 `/opt/astrbot`，安装目录就是 `/opt/astrbot/data/plugins/astrbot_plugin_60sapi_hub`。
   - AstrBot v4.29.1 校验的是插件根目录**解析后**的路径是否仍在 `data/plugins` 边界内：指向该目录之外的符号链接会导致后台视图不出现；指向该目录内部真实副本的链接不受这条边界限制。为避开边界问题，推荐直接使用真实目录副本。
2. 用 AstrBot 使用的 Python 环境安装依赖（只安装上节四项，不含 AstrBot 本体）。下例把 `/opt/astrbot` 换成你的实际根目录：

    ```bash
    python -m pip install -r /opt/astrbot/data/plugins/astrbot_plugin_60sapi_hub/requirements.txt
    ```

3. 重启 AstrBot（或在宿主支持时重载插件），确认插件已启用；登录 Dashboard 后打开插件视图“站点管理”。

### 更新

升级顺序是**先停用并备份、再换代码、最后启用**，不要先替换文件再停用：

1. 在后台停用插件，等调度结束、数据库连接关闭（停用后不再写入新的执行记录），然后按“数据目录与备份”复制 `sites.sqlite3` 作为升级前备份。
2. 替换插件目录内容（整目录替换，或先清理旧文件再复制）；目录形态与“安装”一节保持一致，推荐真实目录副本。
3. 若新版依赖有变化，按“安装”第 2 步重新安装依赖。
4. 最后启用插件或使用重载，确认加载日志出现插件名与版本，再打开后台视图核对站点、组合、任务与历史记录仍完整。

数据目录位于插件目录之外（见下节），替换插件目录本身不影响站点、组合、任务、白名单和历史记录。除受支持的旧库迁移外，其他升级场景未验证。

### 卸载

1. 在后台停用插件，避免残留调度和数据库句柄。
2. 删除插件目录 `<ASTRBOT_ROOT>/data/plugins/astrbot_plugin_60sapi_hub`。
3. 数据目录由管理员自行决定：

   - 保留 `<ASTRBOT_ROOT>/data/plugin_data/astrbot_plugin_60sapi_hub/`：重新安装后站点、组合、任务、白名单和执行/调度记录仍在（凭据原件也保存在该库中）。
   - 删除该目录：所有配置与历史一并丢失且无法恢复，重新安装等于全新状态。

### 数据目录与备份

- 数据库位置：`<ASTRBOT_ROOT>/data/plugin_data/astrbot_plugin_60sapi_hub/sites.sqlite3`。目录由宿主 `StarTools.get_data_dir()` 获取，位于插件目录之外，因此替换或删除插件目录不会删除数据。
- schema 版本 10，共 11 张业务表：`sites`、`content_profiles`、`content_profile_items`、`push_tasks`、`push_task_umos`、`push_schedule_state`、`push_schedule_claims`、`push_schedule_skips`、`delivery_executions`、`delivery_targets`、`delivery_pages`。
- 旧库迁移：受支持的 v1～v9 旧库在同一事务内迁移到当前结构，失败回滚并保留旧数据（站点、凭据、组合、任务、白名单和历史都不会被删除或覆盖）。不要手工修改数据库。
- 备份：先在后台停用插件以关闭数据库连接，再复制 `sites.sqlite3` 到插件目录之外的安全位置；恢复时停用插件、替换该文件、再启用。不要在插件运行中直接复制活跃数据库当作备份。
- 数据库包含站点凭据原件，备份文件同样按敏感文件保管，不要提交到仓库或贴进 Issue。

### 中文字体

图片输出（组合预览的“生成图片”、图片输出任务和 `/60s image`）在服务端用 Pillow 绘制中文图片；字体不随仓库分发，由宿主系统提供。

- 自动发现：macOS 实测使用 `Hiragino Sans GB`；Linux 可检测 Noto Sans CJK、WenQuanYi 等常见 CJK 字体。自动发现与显式指定都会校验常见中文字符的实际字形，缺少中文覆盖的字体（例如 Arial）不会被采用。
- 显式指定：设置环境变量 `ASTRBOT_60SAPI_FONT` 指向管理员提供的字体文件（例如 `ASTRBOT_60SAPI_FONT=<字体文件路径>`），随 AstrBot 进程环境生效。
- 找不到合格字体时返回 `font_unavailable` 并明确失败，不会生成缺字或伪造的图片；纯文字与 Markdown 输出不受影响。
- 字体受其自身许可约束，插件不复制、不再分发系统字体。

## 三种主动操作的区别

后台有三类需要手动触发的动作：都在点击按钮之后才请求上游或发送消息，打开页面、保存配置和启动插件都不会自动执行。区别在于最后是否真的发送消息：

| 操作 | 位置 | 请求上游 | 发送消息 | 对数据的影响 |
|---|---|---|---|---|
| 内容预览 | “内容预览”或“组合预览”区域 | 会请求，可能命中 300 秒缓存 | 不会 | 不改配置；读写页面预览缓存 |
| 测试连接 | 站点卡片“测试连接” | 会请求所选的一个固定接口 | 不会 | 不改配置和 revision；不读写内容缓存；不生成图片 |
| 测试投递 | 任务卡片“测试投递” | 会按已确认版本的组合读取内容；可能命中内容缓存（默认 TTL 300 秒），**不保证重新请求上游** | **会真的向白名单目标尝试发送** | 不改任务配置；写入执行记录 |

- 前两者是只读验证，可以在后台反复操作；第三个是真实发送动作，只有管理员确认后才会执行。成功仅代表宿主发送调用正常完成，不代表平台已读或收件人确认收到。
- 真实账号发送尚未验证：目前只在隔离宿主配合假机器人完成验收。用已连接账号点“测试投递”时，会真的向确认页列出的群聊/私聊目标发送消息。

## 完整操作顺序（每步是否发消息）

1. **准备 60s API 站点**：自行搭建或部署，或使用你有权访问的现有 60s API 站点，需提供 `/v2/60s`（每日新闻）、`/v2/bili`（Bilibili 热搜）、`/v2/zhihu`（知乎热榜）、`/v2/douyin`（抖音热搜）、`/v2/toutiao`（今日头条热榜）等接口。插件不提供站点，也不代理第三方服务。— 发消息：否
2. **配置站点**：Dashboard → 插件视图“站点管理” → 新增站点，填名称、基础地址（不应以 `/v2` 结尾）、超时和可选凭据，保存后确认启用。— 发消息：否
3. **验证站点并预览内容**：在站点卡片点“测试连接”分别验证五种接口；或在“内容预览”选择内容类型点“获取内容”，检查地址、网络和数据结构。— 发消息：否
4. **创建内容组合**：选择站点、勾选 1～5 个内容类型、调整顺序与每栏条数并保存；组合预览可查看纯文字、Markdown 和分页图片。— 发消息：否
5. **获取完整 UMO**：在目标群聊或私聊发送 AstrBot 内置 `/sid`，复制完整标识（格式 `平台适配器实例ID:消息类型:完整会话ID`）。— 发消息：否
6. **创建推送任务**：选择组合与输出方式（纯文字/Markdown/图片），逐行填写 UMO 白名单并保存。任务保存后默认停用，不会自动推送。— 发消息：否
7. **手动测试投递（建议至少做一次）**：任务卡片点“测试投递”→ 核对任务、组合、目标与配置版本 → “确认并投递”。— 发消息：**是，会真的向白名单目标尝试发送**（真实账号尚未验证）
8. **启用计划**：在任务页面选择每日/每周/间隔/Cron 计划并显式启用，启用后才按计划投递。— 发消息：按计划时间才会（真实平台定时投递尚未验证）

聊天命令（`/60s list`、`/60s get`、`/60s image`）只回复执行命令的会话，不发往白名单，详见“聊天查询命令”。

## 获取白名单标识

使用 AstrBot 内置 /sid 获取当前会话 UMO，具体见 [配置说明](configuration.md)。插件不要求额外绑定操作。空白名单不发送。

如果改过指令前缀，应使用对应前缀。群聊隔离场景须确认群级推送标识，不能只凭纯群号猜测平台。

## 功能细节

以下按后台页面的区域说明每项功能的操作方式与边界。

### 站点管理

在隔离的 AstrBot v4.29.1 中，登录 Dashboard 后可打开插件视图“站点管理”：

- 查看已保存站点，新增、编辑或删除站点。
- 修改名称、基础地址、启用状态和超时；地址支持内网、Docker 主机名、方括号 IPv6 和反向代理路径前缀，不应以 `/v2` 结尾。
- 编辑凭据时默认保留原值，也可设置新值或清除；保存后只显示“已设置/未设置”，不会回显原文。
- 站点保存只做服务端格式校验，不会请求 60s API；内容预览和测试连接都是单独的主动操作。字段校验失败会保留已填写的表单，修正后可再次提交；revision 冲突会重新读取列表，不自动覆盖他人修改。
- 如果保存或删除过程中网络中断、超时或响应丢失，页面会进入“结果未确认”状态：服务器可能已经完成，也可能没有收到请求。此时保存/删除按钮和关闭操作会被锁住，不能直接重复提交；请先点击“重新读取最新列表”。重新读取失败时会继续保持未确认。重新读取成功后，页面会显示最新列表状态；系统不会仅凭名称或地址判断新增记录是否来自本次提交，请人工检查列表后再决定是否关闭并重新打开表单。

### 内容预览

在“内容预览”区域选择一个已启用站点和内容类型，点击“获取内容”。打开页面、切换类型、保存站点和启动插件都不会自动请求上游；只有点击按钮才会获取选中的 endpoint。

**每日新闻**

- 显示来源站点、接口 `/v2/60s`、上游内容日期、获取时间和按上游顺序排列的新闻条目；条数按实际返回，不固定为 15 条。
- 上游返回 `news: []` 时显示“合法空内容”，这不是错误。
- 内容日期缺失或无法识别时显示“未知”；内容日期早于当前中国日期时会提示旧内容，但保留原日期，不会用抓取时间冒充今天。

**Bilibili 热搜**

- 显示来源站点、接口 `/v2/bili`、获取时间、实际条数和按上游顺序排列的标题/可选链接。
- 上游返回 `data: []` 时显示合法空列表，这不是错误。
- 当前接口没有排名、热度或更新时间；页面不显示这些指标，也不把列表序号当排名。获取时间是本插件的请求时间，不是上游更新时间。
- 链接缺失或格式不安全时只忽略链接；标题中的 HTML 只作为文本显示，不执行。

**知乎热榜**

- 显示来源站点、接口 `/v2/zhihu`、获取时间、实际条数和按上游顺序排列的标题、可选摘要、原始热度文本和可选链接。
- 上游返回 `data: []` 时显示合法空列表，这不是错误。
- 热度文本（例如“1670 万热度”）原样显示，不换算成数值；当前接口没有排名或更新时间，页面不显示这些指标，也不把列表序号当排名。
- 封面图片地址不渲染，不会自动请求远程图片；标题、摘要、热度中的 HTML 只作为文本显示。
- 链接缺失或格式不安全时只忽略链接，不影响标题、摘要和热度。

五种内容切换后旧结果会清空，不会把其他内容类型的结果显示成当前类型。网络、HTTP、业务结构、缓存等待超时或响应过大失败会显示错误，按钮恢复后可主动重试；失败不会保存、删除站点或发送消息。

**缓存与刷新**

- “获取内容”优先使用 300 秒内成功获取的快照，命中时不会请求上游；“刷新上游”跳过已完成缓存，强制重新获取。
- 缓存最多 32 项，按最近使用淘汰；只缓存成功结果，合法空列表也会缓存，错误不会缓存。
- 结果中的“缓存”显示“缓存命中”或“本次上游获取”，“缓存有效至”显示本地时间的过期时刻；原“获取时间”和内容日期不会因缓存命中改变。
- 刷新失败会明确报错，不会把旧数据说成刷新成功；如果上一份缓存仍未过期，之后点“获取内容”仍可看到它。
- 站点改名、改地址或修改凭据后，旧缓存不会复用；站点停用或删除后不会继续返回缓存。
- 每日新闻跨中国日期后不会继续使用昨日缓存，重新获取并重新计算旧内容提示。
- 预览缓存只在当前进程内有效；插件停用、重载或 AstrBot 重启后清空。旧每日新闻独立 API 保持原有响应，不受本页缓存按钮影响。

### 内容组合

- 在“内容组合”区域新建组合：填写名称、选择一个已保存站点，勾选 1～5 个现有内容类型，使用“上移/下移”调整顺序，并在每栏填写最多展示条数。留空表示展示全部，正整数范围为 1～1000。
- 当前五类接口没有可配置参数，页面不展示参数编辑器；组合只引用已保存站点和现有类型，不能填写任意 URL。
- 可以引用已停用站点保存组合，但预览会明确提示站点未启用，不发起上游请求。
- “组合预览”只请求组合选中的栏目，按配置顺序显示，并按每栏条数截取；单内容预览仍显示完整列表。普通获取使用缓存，“刷新组合”跳过已完成缓存。
- 结果分为“完整成功”“部分成功”“全部失败”。部分失败会保留成功的栏目并列出失败栏目和安全错误；全部失败不会显示成空内容成功。合法空列表算成功。
- 组合编辑/删除使用 revision 冲突保护；被组合引用的站点不能删除，页面会提示引用关系。写操作响应丢失时先重新读取组合列表确认，不直接重复提交。
- 组合列表刷新后，如果当前组合的名称、revision、站点或栏目配置发生变化，或当前组合被删除，页面会清除当前组合预览，不会把旧 revision 的结果继续显示。编辑/删除当前组合也会立即失效旧预览。
- 暂扣的旧预览响应即使稍后返回也不能覆盖新配置；旧请求不会清除新请求的忙状态。失效只清除页面结果，不会自动重新请求上游。
- 组合保存在插件数据目录的 SQLite 中，重启后保留；组合内容快照不持久化。
- 成功或部分成功的组合预览下方提供“纯文字”和“Markdown 源码”切换、复制和下载。两种格式来自同一次预览结果，切换格式、复制或下载不会重新请求上游。
- 下载文件为 UTF-8 的 `60sapi-profile-<组合 ID>.txt` 或 `.md`，不会直接使用组合名称拼接文件名。
- 复制会锁定本次操作的格式、文本和输出身份；完成后如果格式、预览、组合或输出已经变化，不会修改新的提示、焦点或选区。多次复制并发时只让最新操作更新提示。
- 复制只有浏览器实际写入剪贴板成功后才提示成功；如果宿主 iframe 或浏览器拒绝剪贴板权限，页面会选中当前文本并提示手动复制。当前隔离 AstrBot v4.29.1 iframe 复核的是权限拒绝后的降级路径；成功回调分支使用可控 Promise 验证，不代表真实系统剪贴板写入成功。
- 全部失败、组合切换、编辑、删除或列表使预览失效时，旧输出会清除，复制和下载按钮禁用；不会把旧文本当作本次结果。
- 成功或部分成功预览提供“生成图片”按钮。图片是显式操作，打开页面、保存配置、切换文字/Markdown 或复制不会自动生成。
- 图片使用同一次预览的短期快照，不会重新请求 60s API，也不会读取后来更新的缓存；服务端按排版分页，页面显示每页图片并可逐页下载 PNG。
- 图片包含组合名、来源、成功/部分成功状态、预览生成时间、栏目获取时间、真实时间/日期提示、标题、摘要、热度和页码；部分失败栏目以红色说明。全部失败不生成图片。
- 图片固定页面为 900×1200，最多 6 页；超过页数、总像素、单页/总字节或渲染时间会明确提示失败，文字和 Markdown 保持可用。图片生成和下载不消耗上游请求次数。
- 组合或站点被修改、删除、停用，快照过期，或当前用户与快照归属不一致时，图片生成会要求重新预览，不会静默替换内容或重新获取。快照默认有效 300 秒。
- 图片下载文件名为 `60sapi-profile-<组合 ID>-page-<页码>.png`，不会使用组合名称或服务器路径。图片样式固定，暂不支持主题编辑、封面、远程字体或远程图片。

### 测试连接

站点卡片提供“测试连接”。对话框显示站点名和当前 revision，只能选择五种内容接口之一（每日新闻 `/v2/60s`、Bilibili 热搜 `/v2/bili`、知乎热榜 `/v2/zhihu`、抖音热搜 `/v2/douyin`、今日头条热榜 `/v2/toutiao`），点击“开始测试”才会主动请求上游；打开页面、打开对话框、切换接口和保存站点都不会自动测试。

- 测试是独立的只读验证：不保存或修改站点配置，不改变启用状态和 revision，不读取也不写入内容缓存，不发送任何消息，不生成图片。
- 停用站点也可由管理员显式测试；测试成功不会把站点改为启用，内容预览和推送仍按原启用状态处理。
- 只验证所选接口：成功表示该接口本次连接成功、上游 JSON 结构符合约定。其他四个接口需分别测试，不能据此推断全部可用。
- 上游返回合法空列表时显示“连接成功，接口返回合法空内容”，这是成功而不是错误。
- 结果显示服务端的安全消息和实际耗时；失败只显示固定安全消息，不回显上游正文、HTTP 状态文本或凭据。
- 429：同时进行的连接测试过多（当前上限 2 个）。页面显示通用失败提示“测试失败，请手动重试；未修改站点配置。”并恢复按钮，不自动重试。插件已为繁忙消息保留警告样式，但 AstrBot 4.29.1 的插件视图 bridge 在异常路径会丢弃服务端消息，实测该文案未透传到页面；这是宿主行为，不代表并发限制未生效。
- 503：插件、内容客户端或站点存储当前不可用（例如插件正在停用或重载）。页面提示稍后手动重试或重新打开页面。
- 409：打开对话框后站点已被修改，revision 不匹配。页面以警告样式提示“站点配置已变化”，需关闭窗口、刷新列表后重新测试。
- 请求期间按钮显示“测试中…”并禁用；“关闭”按钮和 Escape 只关闭对话框，不发起请求。关闭窗口或切换接口后，先前请求的返回不会显示在当前窗口，需要时重新测试。

### 推送任务配置

- 在“推送任务”区域新建任务：填写名称、选择一个已保存内容组合、选择纯文字/Markdown/图片输出，并按行填写 UMO 白名单。
- 在目标会话发送 `/sid` 获取完整 UMO。格式为 `平台适配器实例ID:消息类型:完整会话ID`；只接受 `GroupMessage` 或 `FriendMessage`，不能填写裸群号或 UID。只去掉整条输入的首尾空白；平台字段含空白会报错，会话 ID 内部内容和冒号原样保留。群成员隔离会话 ID 不会自动改写为群级目标。
- 支持群聊/私聊混合、空名单、去重保序和会话 ID 内多个冒号；后端统一接收数组，页面一行一项。平台适配器当前未连接不影响保存，但保存成功不代表已确认可发送。
- 任务可引用站点已停用的组合，便于提前配置；但必须引用实际存在的组合。
- 每个任务最多 20 个 UMO；单个 UMO 最多 512 字符；任务名最多 80 字符。格式错误会明确提示，字段输入保留。
- 任务保存后保持未启用，没有自动推送或下次执行时间。任务卡片提供独立的“测试投递”按钮，只有显式确认才进入投递。
- 删除被任务引用的组合会被阻止，页面显示引用任务名称。删除任务不会删除组合或站点。
- 任务保存/删除的写响应丢失时沿用“结果未确认 → 锁定写入 → 重新读取 → 人工确认”；系统不会按名称推断哪条记录来自本次操作，也不自动重提。
- 任务配置保存在插件数据目录 SQLite，刷新页面、停用/启用和重载后保留；配置文件、启动、打开页面和保存操作不发送消息、不请求上游。

### 后台手动测试投递

当前发送适配仅支持 AstrBot v4.29.1 的 aiocqhttp/OneBot v11；其他平台明确拒绝。接口已接入实际发送路径，隔离验收使用假机器人；真实账号尚未验证。使用已连接账号测试时，确认操作会尝试向列出的白名单目标发送消息。

1. 在任务卡片点击“测试投递”。确认页只读取最新配置，不获取上游内容或发送消息。
2. 核对任务、组合、站点、输出方式、配置版本和每个完整 UMO 的实际群聊/私聊目标。群成员隔离会话会明确展示实际群路由。空名单、站点停用或无效/不支持目标时不可提交。
3. 点击“确认并投递”后，插件按已确认版本重新发起一次预览请求（不复用页面上已有的旧预览结果），再生成文字、Markdown 源码或分页图片。该请求与手动预览走同一入口，**可能命中内容缓存（默认 TTL 300 秒），因此不保证重新请求上游**。配置版本变化时原确认作废，关闭后重新审阅。
4. 查看本次执行标识及逐目标逐页状态。成功仅代表宿主发送调用正常完成，不代表平台已读或收件人确认收到。

**响应丢失和未确认结果**

- 请求超时、网络中断或 `unknown` 都不能证明未发送。使用“只查询该标识”查询原执行，不重复提交。
- 当前页面按任务保存未确认执行；再次打开同一任务会查询原执行，不直接另建测试。不同任务的未确认标识互不覆盖。
- “仅隐藏提示”保留标识，可通过“查看未确认执行”恢复查询入口。
- 宿主 iframe 通常禁止本地存储，此时标识只保存在当前页面内存。刷新后需从服务端执行记录人工核对；若服务端尚未留下记录，不能仅因查询不到就认定未发送。不要把刷新当作重发步骤。
- 当前没有强制解除未知结果或自动重发入口；应先人工核实平台结果。后台不能将未知状态擅自判成失败。

**执行记录**

“手动测试与执行记录”默认显示最近 20 条，“加载更多”继续读取；详情只读，显示目标和页状态，不提供重发按钮。删除任务后历史仍保留。记录不保存完整正文或 PNG，查询不触发获取、渲染或发送。

### 定时计划

任务编辑页的“定时计划”可选择“无计划”“每日”“每周”“间隔”或“Cron”。间隔计划填写指定 IANA 时区的本地起点和固定分钟数；间隔按固定经过时间计算，跨 DST 时本地显示时间可能变化。Cron 仅支持五字段分钟级子集，例如 `30 8 * * 1-5` 表示周一至周五 08:30；Cron 星期 0/7 为周日、1～6 为周一至周六，日与星期同时受限时取并集。不支持秒、年份、英文名称、L/W/#/? 等扩展语法；无有效候选或超出八年搜索范围时不可启用。每周至少选择一个 ISO 星期，weekly 的 1～7 对应周一至周日。任务卡片根据服务端状态显示“启用定时调度”或“停用定时调度”，确认框会展示目标白名单、计划参数和时区；仅管理员页面可操作。每日模式明确填写时间和 IANA 时区，默认展示 `Asia/Shanghai` / `08:30`，不会根据浏览器时区自动推断。任务列表读取真实启停状态和实际下次执行，并显示“计划：每日 HH:mm · 时区”和服务端返回的理论下次时间，并标注任务启停状态、服务端 UTC 和评估时间；实际下次执行单独显示。

- 新建默认无计划；省略计划编辑其他字段不会清除已保存计划。
- 选择“无计划”并保存会显式提交 `null` 清除计划。
- 若服务端返回 `schedule_error`，页面展示中文不可计算提示并保留原始字段；未修改计划时编辑其他字段仍保留计划，也可明确修正或清除。
- 理论时间只是配置预览，不代表定时发送已启用；刷新任务列表可重新获取，不新增轮询。
- 无计划时每日时间和时区字段隐藏且不参与表单校验；已保存的异常计划只要未修改就会原样保留，也可明确清除或修正。
- 任务保存后仍保持未启用；只有管理员通过后台按钮或受鉴权 API 显式启用，才会从未来计划进入调度。启用后普通编辑会自动停用，需要重新启用。
- 迟到窗口 60 秒；超过窗口或启动时已过去的时刻不补发。结果未知不自动重试。任务列表还提供只读的调度认领/跳过记录，不提供重试或补发。

### 聊天查询命令

在任意会话发送以下命令，命令只回复当前会话：

- `/60s` 或 `/60s help`：显示命令帮助。
- `/60s list [页码]`：列出当前会话可见的已保存任务，每页最多 10 项。
- `/60s get <任务ID>`：查询该任务的纯文字内容预览，只回复当前会话。
- `/60s image <任务ID>`：查询同一任务并生成中文分页图片，在一次回复中按页序发送。

聊天列表只返回任务 ID、名称和输出方式。仅显示与当前事件完整 UMO 精确匹配、引用的组合存在且来源站点启用的任务；空白名单、目标被移除、站点停用和组合缺失的任务不会出现。任务未启用仍可被列出，但列表不表示自动推送已启用。

`get` 始终返回纯文字，即使任务配置的输出方式是 Markdown 或图片，也不会改变任务配置或生成图片。查询使用现有组合缓存；不会 force refresh。内容包含来源、内容日期、获取时间和部分失败说明；合法空内容会明确显示，全部失败不会用旧结果冒充成功。授权失败、站点停用、配置变化和任务/目标变化不会请求或输出旧内容。

命令仅回复当前会话，不修改任务、创建投递记录或向白名单主动广播。

## 常见问题

**聊天列表为什么看不到某个任务？**

先确认当前会话 UMO 与任务白名单完全一致（可用 `/sid` 核对），且任务引用的组合存在、来源站点已启用。命令不会因为聊天管理员身份扩大可见范围，也不会回退到群级 UMO；不会泄露其他任务是否存在。

**保存时网络中断，能直接再点一次保存吗？**

不能。网络异常不能证明服务器没有保存；直接重试可能新增重复站点或重复修改。页面会要求先重新读取最新列表。重新读取成功前不要刷新或重复提交；确认列表状态后，再按页面提示关闭并重新操作。

**接口站点在浏览器能打开，插件却连不上？**

请求从 AstrBot 所在设备/容器发出，需要检查该环境的网络。容器里的 localhost 通常指容器本身，不能直接当作其他服务地址。

**Markdown 为什么在聊天中不是网页样式？**

不同平台对 Markdown 的支持不同。后台可以提供标准预览；聊天会使用平台支持的格式或文字/图片。

**为什么旧新闻没发？**

任务会根据内容日期判断是否为今日；旧内容按策略跳过或等待更新。

**后台显示生成成功，但消息没到？**

获取、渲染和投递是不同步骤。检查具体目标的发送记录、平台权限和连接状态。主动推送窗口和媒体限制取决于平台。

**重启后会补发所有漏掉的日报吗？**

没有补发机制。重启只恢复配置及已有记录：未开始的遗留项记为跳过，可能已发送的项保守记为 unknown，不自动补发或重试。计划按配置执行，迟到窗口 60 秒，超过窗口或启动时已过去的时刻不补发。

**为什么插件装上后后台看不到“站点管理”视图？**

先确认插件目录形态：若用符号链接，宿主校验的是解析后路径是否仍在 `data/plugins` 边界内，指向边界之外的链接不会显示视图（见“安装”）；推荐改用真实目录副本。再确认插件已启用并已重启或重载 AstrBot。

**生成图片失败，提示找不到字体怎么办？**

见“中文字体”：安装带中文覆盖的 CJK 字体，或设置 `ASTRBOT_60SAPI_FONT` 指向管理员提供的字体文件。缺字体时返回 `font_unavailable`，纯文字和 Markdown 输出仍可用。

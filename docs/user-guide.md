# 使用手册

**当前为开发源码版 `v0.1.0-dev.1`：没有正式发布版本、没有 git tag，只能从仓库源码安装。** 本手册说明如何从仓库源码安装到 AstrBot、配置自己的 60s API 站点、预览内容和配置任务栏目、按任务白名单手动测试投递，以及启用计划。

旧基线实际验证的宿主版本是 AstrBot v4.29.1（Python 3.12.13 与 3.13.13 实测通过）；当前四导航、任务内栏目及任务预览的新流程尚未在真实宿主验证；其他宿主版本未验证，本手册不声明最低兼容版本。真实账号的群聊/私聊发送与真实平台定时投递均尚未验证，后文逐项标注。项目不提供公共 60s API 站点；你可以自行搭建或部署，也可以使用你有权访问的现有 60s API 站点。

## 运行条件

- 宿主 AstrBot v4.29.1：实际验证版本；其他版本未验证，不声明最低兼容版本。
- 一个你有权访问的 60s API 站点：可自行搭建，或选择公共实例预设及自定义地址。预设来自第三方，稳定性和接口版本可能不同；插件不运营或代理这些服务。
- 已连接的消息平台适配器：只在“测试投递”和定时投递时需要；配置站点、预览内容和保存任务不需要平台在线。当前发送适配只覆盖 AstrBot v4.29.1 的 aiocqhttp/OneBot v11。
- Python 依赖：`aiosqlite>=0.21,<1`、`httpx>=0.27,<1`、`Pillow>=10,<15`、`croniter>=6.2.4,<7`，声明在仓库根部 `requirements.txt`，用 AstrBot 所在环境的解释器安装。AstrBot 本体由宿主提供，不由本插件安装。
- 图片输出需要宿主环境具备可用的中文字体，见下文“中文字体”。

## 安装、更新与卸载（开发源码）

以下步骤面向仓库源码安装。插件目录与数据目录是两处独立位置：更新和卸载默认只影响插件目录，数据目录保留。

文中出现的 `<ASTRBOT_ROOT>` 是**占位符**，代表 AstrBot 根目录（包含 `data/` 的那一层）。执行命令前请替换为你的实际绝对路径；不要把 `<...>` 原样粘进终端，命令行会把尖括号当成输入重定向。

### 安装

1. 把仓库内容复制到安装目录 `<ASTRBOT_ROOT>/data/plugins/astrbot_plugin_60sapi_hub`，推荐直接使用真实目录副本（逐目录复制或打包解压）。
   - 例如 AstrBot 根目录是 `/opt/astrbot`，安装目录就是 `/opt/astrbot/data/plugins/astrbot_plugin_60sapi_hub`。
   - AstrBot v4.29.1 校验的是插件根目录**解析后**的路径是否仍在 `data/plugins` 边界内：指向该目录之外的符号链接会导致后台视图不出现；指向该目录内部真实副本的链接不受这条边界限制。为避开边界问题，推荐直接使用真实目录副本。
2. 用 AstrBot 使用的 Python 环境安装依赖（只安装上节四项，不含 AstrBot 本体）。下例把 `/opt/astrbot` 换成你的实际根目录：

    ```bash
    python -m pip install -r /opt/astrbot/data/plugins/astrbot_plugin_60sapi_hub/requirements.txt
    ```

3. 重启 AstrBot（或在宿主支持时重载插件），确认插件已启用；登录 Dashboard 后从左侧栏「60sAPI Hub」进入插件管理页。

### 更新

升级顺序是**先停用并备份、再换代码、最后启用**，不要先替换文件再停用：

1. 在后台停用插件，等调度结束、数据库连接关闭（停用后不再写入新的执行记录），然后按“数据目录与备份”复制 `sites.sqlite3` 作为升级前备份。
2. 替换插件目录内容（整目录替换，或先清理旧文件再复制）；目录形态与“安装”一节保持一致，推荐真实目录副本。
3. 若新版依赖有变化，按“安装”第 2 步重新安装依赖。
4. 最后启用插件或使用重载，确认加载日志出现插件名与版本，再打开后台视图核对站点、任务栏目与历史记录仍完整。

数据目录位于插件目录之外（见下节），替换插件目录本身不影响站点、任务栏目、白名单和历史记录。除受支持的旧库迁移外，其他升级场景未验证。

### 卸载

1. 在后台停用插件，避免残留调度和数据库句柄。
2. 删除插件目录 `<ASTRBOT_ROOT>/data/plugins/astrbot_plugin_60sapi_hub`。
3. 数据目录由管理员自行决定：

   - 保留 `<ASTRBOT_ROOT>/data/plugin_data/astrbot_plugin_60sapi_hub/`：重新安装后站点、任务栏目、白名单和执行/调度记录仍在（凭据原件也保存在该库中）。
   - 删除该目录：所有配置与历史一并丢失且无法恢复，重新安装等于全新状态。

### 数据目录与备份

- 数据库位置：`<ASTRBOT_ROOT>/data/plugin_data/astrbot_plugin_60sapi_hub/sites.sqlite3`。目录由宿主 `StarTools.get_data_dir()` 获取，位于插件目录之外，因此替换或删除插件目录不会删除数据。
- schema 版本 16，共 12 张业务表：`sites`、`content_profiles`、`content_profile_items`、`push_tasks`、`push_task_umos`、`push_task_sites`、`push_schedule_state`、`push_schedule_claims`、`push_schedule_skips`、`delivery_executions`、`delivery_targets`、`delivery_pages`。
- 旧库迁移：受支持的 v1～v15 旧库在事务内迁移至 v16，失败回滚。旧任务引用的组合栏目按原顺序和条数复制为每个任务独立的配置，原组合数据保留；共享旧组合的任务迁移后互不联动，重复启动不会重复复制。旧任务没有候选站点时使用原组合站点，已有候选顺序保留；无来源类型的旧站点迁移为公开，已有类型保留。升级前停用并备份，升级后核对任务栏目和站点；不要手工修改数据库。
- 备份：先在后台停用插件以关闭数据库连接，再复制 `sites.sqlite3` 到插件目录之外的安全位置；恢复时停用插件、替换该文件、再启用。不要在插件运行中直接复制活跃数据库当作备份。
- 数据库包含站点凭据原件，备份文件同样按敏感文件保管，不要提交到仓库或贴进 Issue。

### 中文字体

图片输出（任务预览的“生成图片”、图片输出任务和 `/60s image`）在服务端用 Pillow 绘制中文图片；字体不随仓库分发，由宿主系统提供。

- 自动发现：macOS 实测使用 `Hiragino Sans GB`；Linux 可检测 Noto Sans CJK、WenQuanYi 等常见 CJK 字体。自动发现与显式指定都会校验常见中文字符的实际字形，缺少中文覆盖的字体（例如 Arial）不会被采用。
- 显式指定：设置环境变量 `ASTRBOT_60SAPI_FONT` 指向管理员提供的字体文件（例如 `ASTRBOT_60SAPI_FONT=<字体文件路径>`），随 AstrBot 进程环境生效。
- 找不到合格字体时返回 `font_unavailable` 并明确失败，不会生成缺字或伪造的图片；纯文字与 Markdown 输出不受影响。
- 字体受其自身许可约束，插件不复制、不再分发系统字体。

## 主动操作的区别

后台的测试和预览由管理员主动触发；打开页面或保存配置不会执行这些操作。定时任务启用后会按计划运行。各操作是否发送消息如下：

| 操作 | 位置 | 请求上游 | 发送消息 | 对数据的影响 |
|---|---|---|---|---|
| 内容预览 | “内容预览”或任务卡片“预览内容” | 会请求，可能命中 300 秒缓存 | 不会 | 不改配置；读写页面预览缓存 |
| 测试连接 | 站点卡片“测试连接” | 可单独测试一个接口，也可一键测试全部五类 | 不会 | 不改配置和 revision；不读写内容缓存；不生成图片 |
| 任务能力测试 | 推送任务编辑窗口（新建或编辑） | 按当前表单草稿检查；直接取数，不读写生产缓存 | 不会 | 不保存草稿、不改已保存任务与调度；结果不代表实时连通性 |
| 测试投递 | 任务卡片“测试投递” | 会按已确认版本的任务读取内容；可能命中内容缓存（默认 TTL 300 秒），**不保证重新请求上游** | **会真的向白名单目标尝试发送** | 不改任务配置；写入执行记录 |

- 内容预览、站点测试和任务能力测试不会发送消息；测试投递是真实发送动作，只有管理员确认后才会执行。成功仅代表宿主发送调用正常完成，不代表平台已读或收件人确认收到。
- 真实账号发送尚未验证：目前只在隔离宿主配合假机器人完成验收。用已连接账号点“测试投递”时，会真的向确认页列出的群聊/私聊目标发送消息。

## 完整操作顺序（每步是否发消息）

1. **准备 60s API 站点**：自行搭建或部署，或使用你有权访问的现有 60s API 站点，需提供 `/v2/60s`（每日新闻）、`/v2/bili`（Bilibili 热搜）、`/v2/zhihu`（知乎热榜）、`/v2/douyin`（抖音热搜）、`/v2/toutiao`（今日头条热榜）等接口。插件不提供站点，也不代理第三方服务。— 发消息：否
2. **配置站点**：Dashboard → 左侧栏「60sAPI Hub」 → 插件内左侧导航“站点管理” → 新增站点，先选择公开或自建实例。公开实例可选预设或自定义地址，自建实例直接填写地址；再填名称、超时和可选凭据，保存后确认启用。基础地址不应以 `/v2` 结尾。— 发消息：否
3. **验证站点并预览内容**：在站点卡片点“测试连接”，选择单项或一键测试五种接口；或在“内容预览”选择内容类型点“获取内容”。— 发消息：否
4. **获取完整 UMO**：在目标群聊或私聊发送 AstrBot 内置 /sid，复制完整标识。— 发消息：否
5. **创建推送任务**：直接添加 1～5 个栏目、调整顺序与条数，选择输出方式与图片样式，依次添加候选站点并填写 UMO 白名单。编辑窗口可直接用当前表单草稿测试候选站点、预览内容和生成图片，无需先保存；保存后任务默认停用。— 发消息：否
6. **预览任务**：在任务卡片点击“预览内容”，按已保存栏目和候选顺序获取；可查看、复制或下载纯文字和 Markdown，并显式生成每栏目一张长图。— 发消息：否
7. **手动测试投递**：任务卡片点“测试投递”，核对任务、栏目、候选站点、目标与配置版本后确认。— 发消息：**是，会真的向白名单目标尝试发送**（真实账号尚未验证）
8. **启用计划**：在任务页面配置计划并显式启用，启用后按计划投递。— 发消息：按计划时间才会（真实平台定时投递尚未验证）

聊天命令（`/60s list`、`/60s get`、`/60s image`）只回复执行命令的会话，不发往白名单，详见“聊天查询命令”。

插件安装并启用后，AstrBot 主界面左侧栏会显示「60sAPI Hub」入口，点击直接进入本插件的管理页（地址仍为 `/#/plugin-view/astrbot_plugin_60sapi_hub/sites`），沿用宿主的拼图图标、选中高亮和登录鉴权。停用或卸载插件后，刷新页面该入口消失；重新启用或重装后只恢复一个入口。

## 获取白名单标识

使用 AstrBot 内置 /sid 获取当前会话 UMO，具体见 [配置说明](configuration.md)。插件不要求额外绑定操作。空白名单不发送。

如果改过指令前缀，应使用对应前缀。群聊隔离场景须确认群级推送标识，不能只凭纯群号猜测平台。

## 功能细节

后台采用左侧导航（窄屏为顶部紧凑导航），共四个区域，同一时刻只显示当前区域：

| 导航 | 包含内容 |
|---|---|
| 站点管理 | 站点列表、新增/编辑/删除、测试连接 |
| 内容预览 | 单类内容预览与“刷新上游” |
| 推送任务 | 任务栏目、候选站点、内容预览、UMO 白名单与定时计划 |
| 执行记录 | 手动测试投递记录与定时调度记录（分区展示） |

切换导航只改变显示，不请求上游、不发送消息，也不清除未确认的写入或投递状态。以下按区域说明每项功能的操作方式与边界。

### 站点管理

在隔离的 AstrBot v4.29.1 中，登录 Dashboard 后从左侧栏「60sAPI Hub」进入，再在插件内左侧导航选择“站点管理”：

- 查看已保存站点，新增、编辑或删除站点。名称留空时使用规范化后的完整基础地址；新增或改名不能与已有站点同名，旧库已有同名站点可保持原名编辑其他设置。
- 修改名称、基础地址、来源类型、启用状态和超时；地址支持内网、Docker 主机名、方括号 IPv6 和反向代理路径前缀，不应以 `/v2` 结尾。
- 公开实例可选内置预设或“自定义地址”；自建实例填写自己的基础地址。预设参考 [60s API 公共实例列表](https://docs.60s-api.viki.moe/7306811m0)，地址与服务状态可能变化，可主动测试连接；选项切换不会自动请求上游。
- 编辑凭据时默认保留原值，也可设置新值或清除；保存后只显示“已设置/未设置”，不会回显原文。修改到不同服务地址时页面默认选择清除原凭据并提示；如确需沿用，可手动选择保留。撤回到原服务时，页面会撤销自动选择的清除。
- 站点保存只做服务端格式校验，不会请求 60s API；内容预览和测试连接都是单独的主动操作。字段校验失败会保留已填写的表单，修正后可再次提交；revision 冲突会重新读取列表，不自动覆盖他人修改。
- 如果保存或删除过程中网络中断、超时或响应丢失，页面会进入“结果未确认”状态：服务器可能已经完成，也可能没有收到请求。此时保存/删除按钮和关闭操作会被锁住，不能直接重复提交；请先点击“重新读取最新列表”。重新读取失败时会继续保持未确认。重新读取成功后，页面会显示最新列表状态；系统不会仅凭名称或地址判断新增记录是否来自本次提交，请人工检查列表后再决定是否关闭并重新打开表单。

### 内容预览

在左侧导航选择“内容预览”，选择一个已启用站点和内容类型，点击“获取内容”。打开页面、切换类型、保存站点和启动插件都不会自动请求上游；只有点击按钮才会获取选中的 endpoint。

**每日新闻**

- 显示来源站点、接口 `/v2/60s`、实际接口地址、上游内容日期、获取时间和按上游顺序排列的新闻条目；条数按实际返回，不固定为 15 条。
- 上游返回 `news: []` 时显示“合法空内容”，这不是错误。
- 内容日期缺失或无法识别时显示“未知”；内容日期早于当前中国日期时会提示旧内容，但保留原日期，不会用抓取时间冒充今天。

**Bilibili 热搜**

- 显示来源站点、接口 `/v2/bili`、实际接口地址、获取时间、实际条数和按上游顺序排列的标题/可选链接。
- 上游返回 `data: []` 时显示合法空列表，这不是错误。
- 当前接口没有排名、热度或更新时间；页面不显示这些指标，也不把列表序号当排名。获取时间是本插件的请求时间，不是上游更新时间。
- 链接缺失或格式不安全时只忽略链接；标题中的 HTML 只作为文本显示，不执行。

**知乎热榜**

- 显示来源站点、接口 `/v2/zhihu`、实际接口地址、获取时间、实际条数和按上游顺序排列的标题、可选摘要、原始热度文本和可选链接。
- 上游返回 `data: []` 时显示合法空列表，这不是错误。
- 热度文本（例如“1670 万热度”）原样显示，不换算成数值；当前接口没有排名或更新时间，页面不显示这些指标，也不把列表序号当排名。
- 封面图片地址不渲染，不会自动请求远程图片；标题、摘要、热度中的 HTML 只作为文本显示。
- 链接缺失或格式不安全时只忽略链接，不影响标题、摘要和热度。

五种内容切换后旧结果会清空，不会把其他内容类型的结果显示成当前类型。网络、HTTP、业务结构、缓存等待超时或响应过大失败会显示错误，按钮恢复后可主动重试；失败不会保存、删除站点或发送消息。

**来源地址**

站点有一个“来源类型”设置，决定内容输出里怎么显示来源：

- **公开服务**：只显示域名（例如站点填 `https://api.example.com/secret-path` 时显示 `api.example.com`），不显示协议、端口、路径、查询串、用户信息或凭据。
- **自建服务**：只显示“自建服务”，不显示地址，适合内网、Docker 主机名或不想公开的自建站点。新建站点默认公开，使用自建站点且不想公开其主机名时应手动选择“自建服务”。
- 显示值不包含 Bearer 凭据、URL 用户信息、路径、查询串和 fragment；凭据仍只随请求头发送。管理员在后台站点管理和受鉴权接口中仍可看到完整配置地址。
- 若站点列表显示“来源类型未知”，编辑页面会提示管理员；未选择来源类型时页面不会提交该字段。明确选择公开或自建后提示消失，并按所选类型保存。最终能否保留未知值取决于后台对该值的支持。
- 旧版已迁移为自建的站点会保留自建类型；若希望显示域名，请在站点管理中编辑并选择公开服务。无法区分旧版默认值和用户明确选择，因此不会自动改写。
- 站点之后改名、改地址或改来源类型，不会改写已经获取的快照；旧缓存或旧快照没有来源信息时显示“来源不可用”，有地址但没有类型时按自建隐藏，不会用站点名称或接口路径补造。

**缓存与刷新**

- “获取内容”优先使用 300 秒内成功获取的快照，命中时不会请求上游；“刷新上游”跳过已完成缓存，强制重新获取。
- 缓存最多 32 项，按最近使用淘汰；只缓存成功结果，合法空列表也会缓存，错误不会缓存。
- 结果中的“缓存”显示“缓存命中”或“本次上游获取”，“缓存有效至”显示本地时间的过期时刻；原“获取时间”和内容日期不会因缓存命中改变。
- 刷新失败会明确报错，不会把旧数据说成刷新成功；如果上一份缓存仍未过期，之后点“获取内容”仍可看到它。
- 站点改名、改地址或修改凭据后，旧缓存不会复用；站点停用或删除后不会继续返回缓存。
- 每日新闻跨中国日期后不会继续使用昨日缓存，重新获取并重新计算旧内容提示。
- 预览缓存只在当前进程内有效；插件停用、重载或 AstrBot 重启后清空。旧每日新闻独立 API 保持原有响应，不受本页缓存按钮影响。

### 任务内容预览

在“推送任务”的已保存任务卡片点击“预览内容”，或在编辑窗口直接预览当前表单草稿。前者使用该任务已保存的栏目、顺序、条数和候选站点顺序；后者使用当前草稿（含未保存修改）。两者都依次寻找第一个同时满足所有栏目与条数的启用站点，整次预览只使用该站点。没有满足条件的站点时提示调整配置。已保存任务的普通预览可能命中缓存，“重新获取”强制刷新上游；草稿预览直接取数、不读写生产缓存。预览不发送消息、不修改配置。

- 预览显示实际使用站点和栏目结果；纯文字和 Markdown 源码来自同一次结果，可切换、复制和下载，不会重新请求上游。浏览器拒绝剪贴板时可按页面提示手动复制。
- 点击“生成图片”才使用同一次预览的短期快照生成长图，不重新请求上游。一个栏目一张，按任务顺序展示，可打开查看器并逐张下载 PNG；空栏目有空状态，生成失败的栏目会说明原因。
- 条目排版按本栏是否有摘要决定：每日新闻、Bilibili、抖音、今日头条没有摘要，热度与标题同行、每条只占一行；知乎等带摘要栏目保留标题后的摘要展开。无摘要栏目按本栏实测热度宽度分配共用列（900px 图宽下最多 180px、不超过正文宽度四分之一），七八位热度完整显示，极长热度限宽单行省略；长标题在热度列前断行，收尾标点不会压住热度，全文仍在文字/Markdown 中。
- 图片宽 900px、最高 8000px；单张 PNG 最多 2 MiB、一次最多 8 MiB、最多 5 个栏目、单栏文本最多 200,000 字符。高度或单图字节超限时，先按实测字宽把超长摘要压到最多两行、必要时一行并加省略号，标题、条目顺序与条数都保留，页面会提示“部分摘要已缩略”，全文仍可在文字/Markdown 中查看；仍无法压到限额内才让该栏目失败并说明原因。快照默认有效 300 秒；配置变化或快照失效时重新预览。草稿预览与已保存任务的图片快照分开淘汰：草稿预览不会让已保存任务的快照提前失效，但快照存储总量仍有上限，任务快照占满时草稿预览可能暂不提供直接出图。
- 来源按快照显示：公开服务只显示域名，自建服务只显示“自建服务”，缺失时显示“来源不可用”。图片样式由任务保存（默认、雾笺、花间、粗体工作室）并随预览快照固定，不加载远程图片或字体。

### 测试连接

站点管理的“批量连接测试”可选择一个类别或全部五类，并选择多个站点；默认勾选启用站点，也可手动选择停用站点。结果按站点和类别显示，不发送消息或修改配置。

站点卡片提供“测试连接”。对话框显示站点名，可以选择单个内容接口点击“开始测试”，也可以一键测试全部五类：每日新闻 `/v2/60s`、Bilibili 热搜 `/v2/bili`、知乎热榜 `/v2/zhihu`、抖音热搜 `/v2/douyin`、今日头条热榜 `/v2/toutiao`。打开页面或对话框、切换接口和保存站点不会自动测试。

- 测试是独立的只读验证：不保存或修改站点配置，不改变启用状态和 revision，不读取也不写入内容缓存，不发送任何消息，不生成图片。
- 停用站点也可由管理员显式测试；测试成功不会把站点改为启用，内容预览和推送仍按原启用状态处理。
- 单项测试只验证所选接口；一键测试逐项展示五类接口的结果。某一类成功不能推断其他接口可用。
- 上游返回合法空列表时显示“连接成功，接口返回合法空内容”，这是成功而不是错误。
- 结果显示服务端的安全消息和实际耗时；失败只显示固定安全消息，不回显上游正文、HTTP 状态文本或凭据。
- 429：同时进行的连接测试过多（当前上限 2 个）。页面显示通用失败提示“测试失败，请手动重试；未修改站点配置。”并恢复按钮，不自动重试。插件已为繁忙消息保留警告样式，但 AstrBot 4.29.1 的插件视图 bridge 在异常路径会丢弃服务端消息，实测该文案未透传到页面；这是宿主行为，不代表并发限制未生效。
- 503：插件、内容客户端或站点存储当前不可用（例如插件正在停用或重载）。页面提示稍后手动重试或重新打开页面。
- 409：打开对话框后站点已被修改，revision 不匹配。页面以警告样式提示“站点配置已变化”，需关闭窗口、刷新列表后重新测试。
- 请求期间按钮显示“测试中…”并禁用；“关闭”按钮和 Escape 只关闭对话框，不发起请求。关闭窗口或切换接口后，先前请求的返回不会显示在当前窗口，需要时重新测试。

### 推送任务配置

- 在左侧导航选择“推送任务”后新建任务：填写名称、直接添加栏目并选择纯文字/Markdown/图片输出，按顺序选择候选站点，并按行填写 UMO 白名单。页面最多选择五个候选，至少选择一个。
- 任务执行按候选顺序寻找第一个能满足任务中所有栏目和各栏所需条数的启用站点；一次内容只使用该站点，不混用不同站点。栏目条数留空表示不限条数，合法空列表仍可满足该栏；填写正数时条数不足不满足。
- 新建和编辑窗口都可以直接测试候选站点、预览内容与生成长图：使用当前表单草稿（含未保存的修改），不会保存任务，也不会改动已保存任务、调度或投递记录。草稿测试与预览直接取数，不读也不写生产内容缓存，不会影响已保存任务后续看到的缓存内容。
- 草稿能力测试不发送消息，只检查当前栏目、条数与候选顺序；最多检查前五个候选，候选数量或重复项不合法会直接提示。表单一旦修改，上一次测试或预览结果即作废，需要重新测试。
- 所有候选都不能满足时，任务向自己的非空 UMO 白名单发送一条安全的文字异常提示；空名单不发送。内容采集状态与提示投递状态可在执行记录中分别查看。
- 在目标会话发送 `/sid` 获取完整 UMO。格式为 `平台适配器实例ID:消息类型:完整会话ID`；只接受 `GroupMessage` 或 `FriendMessage`，不能填写裸群号或 UID。只去掉整条输入的首尾空白；平台字段含空白会报错，会话 ID 内部内容和冒号原样保留。群成员隔离会话 ID 不会自动改写为群级目标。
- 支持群聊/私聊混合、空名单、去重保序和会话 ID 内多个冒号；后端统一接收数组，页面一行一项。平台适配器当前未连接不影响保存，但保存成功不代表已确认可发送。
- 任务可配置已停用的候选站点，便于提前配置；并至少添加一个栏目。
- 每个任务最多 20 个 UMO；单个 UMO 最多 512 字符；任务名最多 80 字符。格式错误会明确提示，字段输入保留。
- 任务保存后保持未启用，没有自动推送或下次执行时间。任务卡片提供独立的“测试投递”按钮，只有显式确认才进入投递。
- 任务栏目相互独立；删除任务不会删除候选站点，被任务引用的站点不能删除。
- 任务保存/删除的写响应丢失时沿用“结果未确认 → 锁定写入 → 重新读取 → 人工确认”；系统不会按名称推断哪条记录来自本次操作，也不自动重提。
- 任务配置保存在插件数据目录 SQLite，刷新页面、停用/启用和重载后保留；配置文件、启动、打开页面和保存操作不发送消息、不请求上游。

### 后台手动测试投递

当前发送适配仅支持 AstrBot v4.29.1 的 aiocqhttp/OneBot v11；其他平台明确拒绝。接口已接入实际发送路径，隔离验收使用假机器人；真实账号尚未验证。使用已连接账号测试时，确认操作会尝试向列出的白名单目标发送消息。

1. 在左侧导航选择“推送任务”，在任务卡片点击“测试投递”。确认页只读取最新配置，不获取上游内容或发送消息。
2. 核对任务、栏目、候选站点顺序、输出方式、配置版本和每个完整 UMO 的实际群聊/私聊目标。群成员隔离会话会明确展示实际群路由。空名单或无效/不支持目标时不可提交；所有候选停用时确认页会说明只发送异常提示。
3. 点击确认后，插件按已确认配置依次尝试候选站点，选出满足全部栏目及条数的一个站点，再生成文字、Markdown 源码或栏目长图；全部不满足时发送文字异常提示。内容获取**可能命中内容缓存（默认 TTL 300 秒），因此不保证重新请求上游**。配置版本变化时原确认作废，关闭后重新审阅。
4. 查看本次执行标识及逐目标、逐栏目图状态；某栏目未出图时该槽位记为 skipped，不会用其他栏目图替代。成功仅代表宿主发送调用正常完成，不代表平台已读或收件人确认收到。

**响应丢失和未确认结果**

- 请求超时、网络中断或 `unknown` 都不能证明未发送。使用“只查询该标识”查询原执行，不重复提交。
- 当前页面按任务保存未确认执行；再次打开同一任务会查询原执行，不直接另建测试。不同任务的未确认标识互不覆盖。
- “仅隐藏提示”保留标识，可通过“查看未确认执行”恢复查询入口。
- 宿主 iframe 通常禁止本地存储，此时标识只保存在当前页面内存。刷新后需从服务端执行记录人工核对；若服务端尚未留下记录，不能仅因查询不到就认定未发送。不要把刷新当作重发步骤。
- 当前没有强制解除未知结果或自动重发入口；应先人工核实平台结果。后台不能将未知状态擅自判成失败。

**执行记录**

左侧导航选择“执行记录”，区域内含两块：**手动测试投递记录**默认显示最近 20 条，“加载更多”继续读取；详情只读，显示目标与每张栏目图状态，不提供重发按钮。删除任务后历史仍保留。记录不保存完整正文或 PNG，查询不触发获取、渲染或发送。**定时调度记录**（调度认领与跳过）也在本区域，按分页读取，状态语义见“定时计划”。

### 定时计划

任务编辑页的“定时计划”可选择“无计划”“每日”“每周”“间隔”或“Cron”。间隔计划填写指定 IANA 时区的本地起点和固定分钟数；间隔按固定经过时间计算，跨 DST 时本地显示时间可能变化。Cron 仅支持五字段分钟级子集，例如 `30 8 * * 1-5` 表示周一至周五 08:30；Cron 星期 0/7 为周日、1～6 为周一至周六，日与星期同时受限时取并集。不支持秒、年份、英文名称、L/W/#/? 等扩展语法；无有效候选或超出八年搜索范围时不可启用。每周至少选择一个 ISO 星期，weekly 的 1～7 对应周一至周日。任务卡片根据服务端状态显示“启用定时调度”或“停用定时调度”，确认框会展示目标白名单、计划参数和时区；仅管理员页面可操作。每日和每周计划用“小时”“分钟”两个原生下拉选择时间（00～23、00～59，24 小时制，默认 `08:30`），提交时拼成 `HH:mm`；时区用预置下拉，`Asia/Shanghai` 置顶，另有香港、台北、东京、首尔、新加坡、加尔各答、加德满都、迪拜、悉尼、奥克兰、伦敦、柏林、纽约、芝加哥、洛杉矶、圣保罗和 UTC，显示为 `IANA · 中文名`，提交原始 IANA ID。不会根据浏览器时区自动推断；旧任务保存了预置之外合法时区时，会用「已保存：<IANA>」选项原值回填，不改写数据，切换到其他任务时该临时选项不再保留。任务列表读取真实启停状态和实际下次执行，并显示“计划：每日 HH:mm · 时区”和服务端返回的理论下次时间，并标注任务启停状态、服务端 UTC 和评估时间；实际下次执行单独显示。

- 新建默认无计划；省略计划编辑其他字段不会清除已保存计划。
- 选择“无计划”并保存会显式提交 `null` 清除计划。
- 若服务端返回 `schedule_error`，页面展示中文不可计算提示并保留原始字段；未修改计划时编辑其他字段仍保留计划，也可明确修正或清除。
- 理论时间只是配置预览，不代表定时发送已启用；刷新任务列表可重新获取，不新增轮询。
- 无计划时每日时间和时区字段隐藏且不参与表单校验；已保存的异常计划只要未修改就会原样保留，也可明确清除或修正。
- 任务保存后仍保持未启用；只有管理员通过后台按钮或受鉴权 API 显式启用，才会从未来计划进入调度。启用后普通编辑会自动停用，需要重新启用。
- 迟到窗口 60 秒；超过窗口或启动时已过去的时刻不补发。结果未知不自动重试。任务列表还提供只读的调度认领/跳过记录，不提供重试或补发。

### 聊天查询命令

在任意会话发送以下命令，命令只回复当前会话：

- `/60s` 或 `/60s help`：显示命令帮助。
- `/60s list [页码]`：列出当前会话可见的已保存任务，每页最多 10 项。
- `/60s get <任务ID>`：查询该任务的纯文字内容预览，只回复当前会话。
- `/60s image <任务ID>`：查询同一任务并生成中文栏目长图（每栏目一张），按栏目顺序在一次回复中发送，并回报“共 N 张栏目长图”；有栏目未出图时追加一行列出这些栏目。

聊天列表只返回任务 ID、名称和输出方式。仅显示与当前事件完整 UMO 精确匹配、栏目配置有效且至少一个候选站点启用的任务；空白名单、目标被移除、站点停用和栏目配置无效的任务不会出现。任务未启用仍可被列出，但列表不表示自动推送已启用。

`get` 始终返回纯文字，即使任务配置的输出方式是 Markdown 或图片，也不会改变任务配置或生成图片。查询使用现有内容缓存；不会 force refresh。内容包含各栏目的数据来源（公开实例只显示域名，自建站点显示“自建服务”）、内容日期、获取时间和部分失败说明；合法空内容会明确显示，全部失败不会用旧结果冒充成功。授权失败、站点停用、配置变化和任务/目标变化不会请求或输出旧内容。来源展示与后台文字输出一致：公开实例只显示域名，自建站点只显示“自建服务”，都不含协议、端口、路径、凭据、查询串和 fragment。

命令仅回复当前会话，不修改任务、创建投递记录或向白名单主动广播。

## 常见问题

**聊天列表为什么看不到某个任务？**

先确认当前会话 UMO 与任务白名单完全一致（可用 `/sid` 核对），且任务栏目有效且至少一个候选站点已启用。命令不会因为聊天管理员身份扩大可见范围，也不会回退到群级 UMO；不会泄露其他任务是否存在。

**保存时网络中断，能直接再点一次保存吗？**

不能。网络异常不能证明服务器没有保存；直接重试可能新增重复站点或重复修改。页面会要求先重新读取最新列表。重新读取成功前不要刷新或重复提交；确认列表状态后，再按页面提示关闭并重新操作。

**接口站点在浏览器能打开，插件却连不上？**

请求从 AstrBot 所在设备/容器发出，需要检查该环境的网络。容器里的 localhost 通常指容器本身，不能直接当作其他服务地址。

**Markdown 为什么在聊天中不是网页样式？**

不同平台对 Markdown 的支持不同。Markdown 以源码纯文本发送；任务预览可查看和复制源码。

**为什么旧新闻没发？**

当前不会因为内容日期旧而跳过，也不会自动等待上游更新。每日新闻解析时会比对上游内容日期与当前日期：早于当前日期即标记为旧内容并给出提示，同时**保留上游原日期**，不用抓取时间冒充今天。预览、任务渲染和投递展示的都是这个保留的上游日期；投递按已获取到的内容直接发送。

**后台显示生成成功，但消息没到？**

获取、渲染和投递是不同步骤。检查具体目标的发送记录、平台权限和连接状态。主动推送窗口和媒体限制取决于平台。

**重启后会补发所有漏掉的日报吗？**

没有补发机制。重启只恢复配置及已有记录：未开始的遗留项记为跳过，可能已发送的项保守记为 unknown，不自动补发或重试。计划按配置执行，迟到窗口 60 秒，超过窗口或启动时已过去的时刻不补发。

**为什么插件装上后后台看不到“站点管理”视图？**

先确认插件目录形态：若用符号链接，宿主校验的是解析后路径是否仍在 `data/plugins` 边界内，指向边界之外的链接不会显示视图（见“安装”）；推荐改用真实目录副本。再确认插件已启用并已重启或重载 AstrBot。

**生成图片失败，提示找不到字体怎么办？**

见“中文字体”：安装带中文覆盖的 CJK 字体，或设置 `ASTRBOT_60SAPI_FONT` 指向管理员提供的字体文件。缺字体时返回 `font_unavailable`，纯文字和 Markdown 输出仍可用。

# 配置说明

站点配置、后台管理、五种内容预览、组合图文、任务白名单及后台手动投递/执行记录已实现并完成隔离验收。入口已装配 aiocqhttp 发送适配层，真实账号发送尚未验证；聊天纯文字和图片查询已实现；每日/每周/间隔/五字段 Cron 计划配置、理论下次时间预览、页面启停/记录和单循环调度已实现；站点测试连接（五种内容接口）已实现并完成隔离验收，其他热榜和导入未实现。

## 后台站点管理

在 AstrBot Dashboard 左侧栏打开「60sAPI Hub」后，在插件内左侧导航（窄屏为顶部紧凑导航）选择“站点管理”，可以查看站点列表、新增站点、编辑名称/基础地址/启用状态/超时/凭据，以及确认后删除站点。页面会显示加载、空列表、保存、校验失败、revision 冲突和结果未确认状态。字段校验失败会保留已填写的表单内容并允许修正；网络中断、超时或响应丢失时，服务器可能已经保存，页面会锁定写按钮，要求先重新读取最新列表，不能直接重复提交。

后台通过宿主提供的插件 bridge 调用受 Dashboard 鉴权的插件 Web API，不另建 HTTP 服务、登录系统或 token 存储。服务端对每次请求重新校验输入；编辑和删除要求携带期望 revision，冲突时返回明确错误且不自动覆盖，页面重新读取最新数据后由管理员决定是否再次编辑。

新增或编辑站点时先选择公开实例或自建实例。公开实例提供参考 [60s API 公共实例列表](https://docs.60s-api.viki.moe/7306811m0) 的预设及自定义地址；自建实例直接输入地址。预设由第三方提供，稳定性和版本可能变化。选择类型或预设不会自动请求上游。

凭据编辑默认选择“保留原凭据”，另有“设置新凭据”和“清除凭据”。更换到不同服务地址时，页面默认选择清除原凭据并提示；撤回到原服务会撤销系统自动选择的清除。密码输入框不会预填，保存后页面只显示是否已设置，不显示原文。站点保存只做字段和地址格式校验，不发起连通性测试；内容预览是页面中单独的主动操作。

## API 站点

配置名称、基础地址、来源类型、启用状态、可选 Bearer 凭据、超时。来源类型为 `public`（公开实例，内容输出只显示域名）或 `self_built`（自建，内容输出只显示“自建服务”），新建站点默认 `public`；更新请求省略 `source_kind` 时沿用后台读取的当前值。页面遇到未知类型时显示提示，未明确选择时不提交该字段；修改它会增加站点 revision，但不会改写已生成的内容快照。基础地址约定不含 /v2，可包含反向代理前缀；例如 https://api.example.com/news。

后台会提示误填 /v2，避免重复拼接；保留反代前缀。仅允许 HTTP(S)，不在基础地址中包含用户名密码、查询串或 fragment。

管理员可配置明确的内网/Docker 站点。endpoint 使用受控相对路径，普通聊天不能指定任意 URL；跨源重定向不得转发凭据。凭据在返回结果与日志中脱敏。

### 已实现的站点字段

站点由 `core/sites.py` 的站点服务和 `core/site_store.py` 的 SQLite 存储管理。公开站点结构只返回是否已设置凭据，不返回凭据原文。

| 字段 | 规则 |
|---|---|
| id | 新增时生成的稳定 ID，不因改名改变 |
| name | 去除首尾空白后 1～80 个字符，不能包含换行或控制字符 |
| base_url | 去除首尾空白后 1～2048 个字符，规则见下文 |
| enabled | 已移除；旧请求传 `true` 被忽略，传 `false` 返回字段级 400 提示改用任务候选 |
| timeout_seconds | 1～120 秒，默认 10 秒；拒绝布尔值、NaN 和 Infinity |
| bearer_token | 可选，最长 4096 个可见 ASCII 字符；不能包含空白；只返回 `has_bearer_token` |
| revision | 从 1 开始，每次成功编辑加 1 |
| created_at / updated_at | UTC ISO 8601 时间字符串 |

地址规则：

- 仅允许 `http` 或 `https`，必须包含主机名；端口如填写则必须在 1～65535 之间。
- 支持 `localhost`、内网 IPv4、方括号 IPv6、Docker/内网单标签主机名和反向代理路径前缀。
- 拒绝用户名、密码、查询串和 fragment；即使只有一个 `?` 或 `#` 也拒绝。
- 拒绝反斜杠、空白路径和未编码空格；IPv6 不支持 zone ID；主机名按 ASCII 语法检查，国际化域名需使用 punycode。
- 拒绝地址内部的 CR、LF、Tab、NUL 等控制字符；首尾空白仍会按上文规范化。
- 只去除首尾空白和路径末尾的斜杠，保留路径前缀；不做 DNS 查询，也不以公共网络可达性决定是否有效。
- 路径以 `/v2` 结尾时明确报错，避免请求时重复拼接；`/api/v2/news` 等不以 `/v2` 结尾的路径允许。

### 凭据编辑语义

编辑站点时使用 `credential_action` 区分三种操作：

| 操作 | 行为 |
|---|---|
| `keep` | 保留原值，编辑时的默认值；空白表单不会清除原凭据 |
| `set` | 设置新值，必须提供非空凭据 |
| `clear` | 清除凭据，不提交新值 |

凭据原文保存在插件数据目录的 SQLite 中，不进入公开站点结构、日志、错误消息或对象调试输出。数据库文件应按敏感数据保护，不提交或分享。

## 内容预览

后台当前支持五种内容类型，均只请求已保存站点：

| 内容类型 | endpoint | 真实字段 |
|---|---|---|
| 每日新闻 | `/v2/60s` | 内容日期、有序新闻条目、可选微语/来源链接 |
| Bilibili 热搜 | `/v2/bili` | 有序标题和可选搜索链接；没有排名、热度或更新时间字段 |
| 知乎热榜 | `/v2/zhihu` | 有序标题、可选摘要、原始热度文本和可选链接；没有排名或更新时间字段 |
| 抖音热搜 | `/v2/douyin` | 有序标题、原始整数热度值和可选搜索链接；没有排名或更新时间字段 |
| 今日头条热榜 | `/v2/toutiao` | 有序标题、原始整数热度值和可选链接；没有排名、摘要、标签或更新时间字段 |

页面只提交站点 ID 和固定内容类型；服务端从站点存储读取地址、启用状态、超时和凭据。未知内容类型由后端直接拒绝，不会据此拼接或请求任意 URL。站点不存在或未启用会被拒绝。请求不会自动发生在打开页面、切换内容类型、保存站点或启动插件时；必须由管理员主动点击“获取内容”。

### 每日新闻

请求地址由站点 `base_url` 与 `/v2/60s` 拼接，保留反向代理路径前缀；不额外传 `date` 或 `encoding` 参数，JSON 为默认响应。地址支持内网、Docker 主机名和方括号 IPv6，不以公共网络可达性作为配置条件。

结果快照包含来源站点、内容类型、接口路径、来源地址、站点来源类型、获取时间、上游内容日期、警告和按上游顺序排列的新闻条目。来源地址采用 HTTP 客户端的 URL 规范化，保留非默认端口、站点基础地址中的路径前缀和 endpoint，去掉用户信息、查询串和 fragment；点段和默认端口按客户端规则规范化，无法安全表达时来源不可用。公开实例对外只展示域名，自建站点只展示“自建服务”，完全没有来源信息时显示“来源不可用”。管理员可在站点管理中查看完整基础地址。内容日期可能缺失或格式无法识别，此时显示“未知”；早于当前中国日期的内容会明确提示旧内容，但保留来源日期，不用抓取日期覆盖。`data.news: []` 是合法空内容，与 JSON 结构错误或网络失败分开显示。

### Bilibili 热搜

请求地址为站点 `base_url` 与 `/v2/bili` 拼接。该接口当前返回 `data` 数组，条目由 60s API 映射为 `title` 和 `link`；本插件只使用这两个字段，数组顺序即上游返回顺序，实际条数按列表长度显示。

当前响应没有排名、热度或更新时间字段。页面不显示这些指标，也不把列表序号解释为上游排名；获取时间是本插件的请求时间，不是上游更新时间。`data: []` 是合法空列表。标题缺失或不是非空字符串视为结构错误；链接缺失、不是字符串或不是安全的 HTTP(S) 地址时只忽略链接，不会让整次预览失败或执行上游 HTML。

### 知乎热榜

请求地址为站点 `base_url` 与 `/v2/zhihu` 拼接。当前接口返回 `data` 数组，条目使用 `title`、可选 `detail`、可选 `hot_value_desc` 和可选安全 `link`。

`hot_value_desc` 是类似“1670 万热度”的原始文本，插件原样展示，不换算成数值。`detail` 是摘要文本，可为空。`created`/`created_at` 是话题创建时间，不是更新时间；接口没有排名字段。页面不使用数组序号冒充排名，也不显示“更新时间”。`cover` 图片地址不渲染，避免自动请求远程图片。`data: []` 是合法空列表；标题缺失是非空字符串以外的结构错误。

### 抖音热搜

请求地址为站点 `base_url` 与 `/v2/douyin` 拼接。当前只接入文档中的默认实时热搜榜，不提供榜单变体选择。接口返回 `data` 数组，条目使用 `title`、可选原始整数 `hot_value` 和可选安全 `link`。

热度值按上游整数原样展示，例如“热度：12189774”，不擅自换算成“万”或其他单位。接口没有排名字段；数组顺序即上游返回顺序，序号不冒充排名。`event_time/event_time_at`、`active_time/active_time_at` 等时间字段虽存在，但其单位/语义当前未作为更新时间使用，页面不展示；获取时间也不冒充更新时间。`cover` 不渲染，避免自动请求远程图片。`data: []` 是合法空列表；标题缺失或不是非空字符串是结构错误。

### 今日头条热榜

请求地址为站点 `base_url` 与 `/v2/toutiao` 拼接。当前只接入固定默认热榜，无查询参数或榜单变体。接口返回 `data` 数组，条目使用 `title`、可选原始整数 `hot_value` 和可选安全 `link`。

热度值按上游整数原样展示，例如“热度：112229604”，不换算单位。接口没有排名字段；数组顺序即上游返回顺序，页面不把序号当排名。没有摘要、标签、更新时间或独立时间字段；获取时间不冒充更新时间。`cover` 不渲染，避免自动请求远程图片。`data: []` 是合法空列表；标题缺失或不是非空字符串是结构错误。

### 共用获取能力

五种内容共用一个异步 HTTP 客户端、连接池和全局并发上限，不按 endpoint 分别创建客户端。请求使用站点超时作为整体上限，连接超时不超过 5 秒；响应体最多读取 2 MiB；最多尝试 2 次（仅重试网络错误及 408/429/502/503/504），且所有重试都受整体超时约束。重定向一律不跟随，凭据不会转发到重定向目标。共享客户端在插件启用时创建；停用或重载时先拒绝新请求，取消并等待本客户端拥有的在途、排队和重试等待任务，再关闭连接。外部调用取消会继续向调用方传播。

### 缓存与刷新

统一预览使用进程内有界缓存，不新增数据库表、Redis、磁盘缓存或后台刷新：

- 仅缓存成功解析后的不可变内容快照，包括合法空列表；错误不缓存。
- 默认 TTL 300 秒，最多 32 项；过期项读取时清理，容量满时按 LRU 淘汰。TTL 从成功完成获取时开始，使用可注入的单调时钟判断。
- 缓存键包含站点 ID、内容类型/固定 endpoint、明确的空参数和站点 revision；Bearer 令牌不在键、响应、日志或 repr 中。
- 每次读取前重新检查站点存在且已启用。名称、地址、凭据等配置修改会增加 revision，旧版本快照不能被新版本复用；站点删除或停用后不会返回旧缓存。
- 普通“获取内容”有效缓存命中时不请求上游；“刷新上游”绕过已完成缓存，但可复用同键当前在途的获取，不能直接返回旧缓存。同键并发获取合并为一次上游操作。
- 单个等待者取消不影响其他等待者；最后一个等待者取消才取消共享获取。等待有上限（当前 130 秒），不会无限等待。
- 共享获取一旦决定取消，立即从同键等待记录中移除；新的同键请求发起新的获取，不会加入正在取消的旧任务。旧任务仍由缓存生命周期集合管理，`close()` 会等待其清理完成；旧任务不能覆盖新缓存或删除新请求的在途记录。
- 刷新失败不会写入错误或覆盖旧成功缓存；页面明确报错。后续普通获取仍可使用尚未过期的上一份成功缓存。
- 每日新闻若跨中国日期，缓存失效并重新获取，避免展示昨日计算的“非旧内容”状态；快照原 `fetched_at`、内容日期和上游指标不会被缓存命中改写。
- 停用或重载时缓存层先拒绝新操作，取消并等待自有在途任务，清空缓存，再关闭共享 HTTP 客户端；不会留下后台任务。
- 统一预览请求可选 `force_refresh`，缺省 `false`，必须是严格布尔值；字符串、数字、`null` 等返回 400 且不触发上游。
- 统一预览响应额外返回 `cache.hit`、`cache.expires_at`（UTC ISO 8601）和 `cache.ttl_seconds`。`cache.hit=true` 表示未请求上游；`force_refresh` 成功和首次未命中均为 `false`。缓存元信息不写入领域快照，不改变 `fetched_at`。旧每日新闻独立 API 不改变原有响应结构，也不强制使用缓存。

上游 HTTP 错误只显示程序生成的安全提示和数字状态码；HTTP 200 业务错误只显示业务 code。上游错误正文不会进入后台响应或日志，避免其回显 Bearer 凭据或其他敏感文本。每日新闻、Bilibili 热搜、知乎热榜、抖音热搜和今日头条热榜各自实际使用的站点凭据隔离发送。

## 任务栏目与预览

栏目直接保存在各推送任务中，后台不再提供独立内容组合页面，也不注册旧的 `/profiles` CRUD、预览或图片接口。任务的 `items` 按展示顺序配置 1～5 个不同的内容类型；每项 `params` 只接受空对象，`limit=null` 表示不限条数，正整数为 1～1000。任务之间互不共享可变栏目，保存任务不请求上游或发送消息。

任务卡片的“预览内容”使用已保存配置，按候选顺序单站优先：首个能同时满足全部栏目和条数的站点整次使用；没有单站满足时按栏目从候选里拼合，每栏使用同一站点完整列表，不跨站拼条数。拼合后仍缺栏目时返回 200 的部分结果并列出缺项/`missing`，页面与投递据此提示。可选严格布尔值 `force_refresh` 控制刷新；所有栏目都取不到时返回 502 `content_unavailable`，任务获取期间 revision 改变返回 409 `preview_revision_changed`。预览不投递，返回同源文字、Markdown 和可用时的短期图片快照；页面可复制、下载及显式生成图片。

图片请求使用预览返回的 `image_snapshot.id`，以 `{"snapshot_id":"..."}` 提交至任务图片接口；服务端按快照生成，每栏目一张 PNG，不重新请求上游。图片快照有归属、过期和配置版本检查；任务或站点变更需重新预览。空栏目有空状态图片，失败栏目无图片。宽 900px，单图高度上限 8000px、2 MiB，单次合计上限 8 MiB；栏目最多 5 个，单栏文本最多 200,000 字符。后台支持逐张查看、下载和适应宽度/原始尺寸切换；图片不加载远程资源，依赖宿主 CJK 字体。

旧数据库升级到 schema v16 时，为每个已有任务复制其原组合栏目，生成与任务同 ID 的内部方案并更新任务引用；原组合记录仍保留，多个任务不再共享栏目修改。旧组合并不会自动变成新任务，且旧 `profile_id` 不能替代新任务请求中的 `items`。

## 推送任务

任务配置和 UMO 白名单已实现，保存操作不发送、不请求上游。任务可以选择保存每日计划；保存后仍保持未启用。管理员可通过受鉴权 API 显式启用/停用，启用后才进入每日单循环；页面任务卡片根据服务端 enabled 显示启用/停用按钮；鉴权的后台手动测试使用独立投递接口，见下文。

图片样式：`image_style` 取注册表稳定 ID（内置 `default`、`mist`、`floral`、`bold_studio`、`morning`、`midnight`、`beacon`），新建省略时为 `default`。更新时省略字段保留原值，显式提交 `null`、非字符串或未知 ID 返回字段级 400；读取历史未知值安全回退 `default`。样式随任务内容写入图片快照，之后改样式需要重新预览；后台预览、聊天长图、手动与定时图片投递共用同一份快照样式。任务列表响应附带 `image_styles` 注册表选项（id/name/description 与示例卡 `preview` 配色 token）与 `default_image_style`，任务详情和预览响应返回有效 `image_style`。

任务字段：稳定 ID、名称（最多 80 字符）、有序栏目 `items`、有序候选站点、输出方式（`text`、`markdown`、`image`）、图片样式 `image_style`、独立 UMO 白名单、revision、创建/修改时间。页面最多选择五个候选，新建任务必须指定至少一个。旧客户端更新任务时省略 `sites` 会保留原候选顺序；新建请求须显式提供候选。允许空白名单与多个候选；栏目独立保存于任务。

执行按候选顺序单站优先，没有单站满足时按栏目拼合候选站点；同一栏目不跨站拼条数。正数 `limit` 既是栏目需要的条数，也限制展示条数；`null` 沿用不限条数语义，合法空列表可满足该栏。拼合后仍缺栏目时，只向任务的非空白名单发送文字异常提示并记录采集失败。任务能力测试只读且不发送消息，按完整候选顺序检查（历史任务超过新选上限的长列表也全部检查），可能使用内容缓存，返回 `source_mode`（single/multi/missing）、逐栏 `assignments`（含站点与 revision）、`missing`、是否截断及缓存时效；界面展示逐栏来源与缺项。新建或改选候选时上限为 5 个；未改动的历史长列表原序保留，草稿测试/预览携带该任务 ID 且候选与已保存完全一致时检查完整列表。

| 方法与路径 | 用途 |
|---|---|
| `GET /<插件名>/tasks` | 列出任务栏目、站点启用状态和目标数量 |
| `POST /<插件名>/tasks` | 新增任务 |
| `GET /<插件名>/tasks/<id>` | 读取任务 |
| `POST /<插件名>/tasks/<id>/update` | 按 expected_revision 编辑任务 |
| `POST /<插件名>/tasks/<id>/delete` | 按 expected_revision 删除任务 |
| `POST /<插件名>/tasks/<id>/capability-test` | 测试已保存的候选站点是否满足任务，不发送消息 |
| `POST /<插件名>/tasks/<id>/preview` | 按已保存栏目和候选顺序预览内容 |
| `POST /<插件名>/tasks/<id>/image` | 使用任务预览快照生成栏目长图 |

`schedule` 是可选的每日/每周计划配置；普通任务 CRUD 请求中出现 `enabled`、`next_run`、`next_run_at`、`schedule_preview` 或运行状态字段返回 400 `unsupported_enable_request`，不会写入。启停使用独立接口。`expected_revision` 缺失、null、布尔值、零、负数、小数或字符串返回 400 `validation_error`（字段 `expected_revision`），不会写入；合法但过期的整数 revision 返回 409 `revision_conflict`。任务响应返回真实 `enabled`（由启停接口维护，见下文“每日调度启停”）和与它同值的 `can_send`；后台显式测试是否可投递仍由确认接口的 `can_deliver` 单独判定。删除任务不会删除站点。

### 定时计划配置与预览

任务可选保存：

```json
{"kind":"daily","timezone":"Asia/Shanghai","time":"08:30"}
```

- 支持 `kind=daily`、`kind=weekly`、`kind=interval` 和 `kind=cron`；Cron 仅支持五字段分钟级表达式，星期 0/7 均为周日，日与星期同时受限时取并集。间隔计划使用 IANA 时区本地 `start_at`（`YYYY-MM-DDTHH:mm`）和 1～10080 的 `interval_minutes`，从 UTC 锚点按固定经过分钟计算。`weekdays` 为 1～7 的 ISO 星期（1=周一，7=周日），非空、不重复并规范排序；`timezone` 必须是可用 IANA 时区，`time` 严格为 24 小时制 `HH:mm`。
- 未知类型、非法字段、非法时区、非法时间或错误类型返回 400，不猜测或改用 UTC/系统时区。
- 新建省略 `schedule` 为 `null`；编辑省略保留原计划；显式 `null` 清除计划。
- 计划变更与任务字段在同一事务中提交，成功后任务 revision 只增加一次。
- 列表和详情返回 `schedule` 和 `schedule_preview`。预览包含同一次响应使用的 `evaluated_at` 和理论 `next_run_at`；无计划时均为 `null`。
- 当前时间恰好等于计划时间时取次日；DST 不存在的本地时间跳过当天；DST 重复时间只采用第一次出现，第一次已过去时不使用第二次。预览不写入数据库，也不代表自动发送已启用。
- 后台任务编辑页提供“无计划/每日/每周/间隔/Cron”选择；每日和每周用小时、分钟两个原生下拉（`00–23`、`00–59`，24 小时制，默认 `08:30`，提交拼成 `HH:mm`），时区用预置下拉（`Asia/Shanghai` 置顶，提交原始 IANA ID），默认无计划、不从浏览器时区推断。旧任务的非预置合法时区以「已保存」临时选项原值回填，保存时省略 `schedule` 仍保留原计划。列表显示计划、真实启停状态、实际 `next_run_at`、服务端理论下次时间、UTC 标识和评估时间。旧页面省略 `schedule` 的编辑请求会保留计划。
- 如果已保存计划的时区数据暂时不可用，任务仍保留原始计划字段，并返回 `schedule_error=schedule_timezone_unavailable` 和不可计算的 `schedule_preview`；不会伪装成 `schedule=null`。此时普通名称编辑省略 `schedule` 仍原样保留计划，只有显式 `schedule:null` 才清除。恢复时区数据后可重新计算预览。

### 每日调度启停

- 页面任务卡片根据服务端 `enabled` 显示启用/停用；确认框展示任务、组合、输出、实际 UMO、每日时间和时区。
- `POST /<插件名>/tasks/<id>/enable`、`POST /<插件名>/tasks/<id>/disable`，请求只接受 `expected_revision`。
- 启用前校验计划、IANA 时区、任务栏目、UMO 非空和发送适配器支持目标；站点全部停用不会阻止启用，到期时按异常提示规则处理。成功只安排严格晚于当前时刻的下一次执行，不立即获取或发送。
- 启用/停用成功各增加一次任务 revision；过期 revision 返回 409。
- 普通任务编辑成功会自动停用并删除未来计划，必须重新启用。
- 迟到窗口固定 60 秒；运行中到期且迟到不超过窗口执行一次，超过则跳过并安排下一次，不补发多天。
- 启动/重载不补发已过去时刻；同一任务同一 UTC 时刻由数据库唯一认领，重复/并发检查不会重复发送。
- 认领后崩溃或结果不明保留 `unknown`，不自动重试；跳过记录和真实投递记录分开保存。
- `GET /<插件名>/schedule-runs?limit=20&offset=0` 返回有界的认领和跳过记录，用于验收追踪；不返回凭据、异常正文或路径。
- 任务页列表读取真实 `enabled` 和实际 `next_run_at`；`schedule_preview` 仍只是理论时间，两者分开显示。页面提供启停按钮和只读调度记录。

## 推送白名单

每项一个完整 UMO：`平台适配器实例ID:消息类型:完整会话ID`。只在**前两个**冒号处分割，会话 ID 内部的冒号保留；只对整条输入去首尾空白，平台字段、消息类型和会话 ID 内部内容不做 trim。平台字段含任何空白直接拒绝；会话 ID 的前导/内部空白和内部冒号原样保留。按规范化后的完整字符串精确去重并保留首次出现顺序，不改大小写或改写内部内容。合法保存值严格等于整条输入 strip 后的值。

- 平台字段是 AstrBot 平台适配器实例 ID（例如 `aiocqhttp`、`qq_official`），不是固定平台类型名；不能包含冒号、感叹号或空白，最多 128 字符。
- 消息类型只接受 `GroupMessage` 和 `FriendMessage`；`OtherMessage` 等拒绝。
- 会话 ID 不能为空，最多 384 字符；完整 UMO 最多 512 字符。
- 每任务最多 20 个输入项；空白名单合法。拒绝裸群号、裸 UID、缺字段、空字段、非法类型、控制字符、平台 ID 含冒号/感叹号、超出长度或数量限制。
- 支持群聊和私聊混合；格式合法但平台适配器当前未连接的配置可以保存，保存成功不代表已确认可发送。
- `unique_session` 下的群成员隔离会话 ID 原样保留，不擅自改成群级目标；如需群级目标，应按 AstrBot `/sid` 的提示核对并手工填写，不自动猜测。
- 后台提示使用对应会话的 `/sid` 获取完整 UMO，不把 UID 当 UMO；一行一个，后端统一接收字符串数组。名单按任务独立保存，不导入、继承或修改 AstrBot 全局入站白名单，不增加绑定指令。

## 手动测试投递（后台）

管理员可在任务卡片点击“测试投递”。确认页读取最新任务、组合、站点 revision 和全部目标：

- 展示任务、组合、候选站点及顺序、输出方式和配置 revision；候选全部失效时说明确认后发送文字异常提示。确认响应带 `confirmation_version`（当前 2），提交必须原样带回，旧格式确认返回 409 `confirmation_stale` 要求重新审阅。
- 展示每个完整 UMO、平台实例、群聊/私聊实际目标；成员隔离明确标注最终路由到群。
- 无效/不支持目标不静默移除，确认按钮不可用；空名单明确不可投递。
- 确认后按候选顺序获取内容，不复用页面旧预览，但可能使用内容缓存；请求不携带 UMO、正文、URL 或文件路径。
- 提交携带稳定 execution_id、配置 revision 和候选确认快照；确认后配置变化时返回 409，必须重新审阅。站点内容不足或上游失败属于采集失败，按确认页说明发送异常提示。
- 每次明确操作生成新标识；响应丢失只查询该标识，不自动重新 POST。未知执行不自动重发。
- 执行记录查询无副作用；列表默认 20、最多 50，支持 offset/task_id，按创建时间/id 稳定倒序；删除任务后历史保留。
- 公开投影不返回 owner_token、凭据、路径或堆栈；必要 UMO 仅后台鉴权可见。
- 浏览器 bridge 的 GET 分页参数必须通过 `apiGet(endpoint, params)` 传递，不拼查询串；后台默认 20、最大 50，可“加载更多”。
- 一次确认对应一个稳定 execution_id。提交后 running/unknown/超时/响应丢失只查询该标识；不重新启用旧确认按钮、不生成新 ID 重发。revision 冲突作废确认，必须重新审阅。
- 历史详情为只读模式，不沿用旧 preview 或可提交按钮。弹窗维护统一查询上下文：新提交创建 execution_id 时即绑定，历史/未确认/新提交切换时更新或清除，查询按钮始终使用当前显示的执行标识。查询历史 A 不会清除待确认 B；只有标识匹配的结果才能清除对应尝试。
- 未确认执行按任务分别追踪；同任务再次打开测试进入原执行查询，不同任务互不覆盖。隐藏提示保留“查看未确认执行”入口；历史详情重试只查询该详情的标识。
- iframe 禁用 localStorage 时，当前页内存仍保存未确认标识并可查询；刷新后无内存恢复，只能从执行记录人工核对，不能自动重发或放宽 sandbox。
- 预览、提交、详情查询和弹窗切换均做请求归属检查；迟到响应不能覆盖新弹窗、清除其他执行标识或解除新请求忙状态。
- 启动、保存、预览、查询、停用和重载零发送；只有手动提交进入投递服务。任务 enabled 仍不可修改。



本轮支持 **仅 AstrBot v4.29.1 的 aiocqhttp/OneBot v11 适配器**，其他适配器明确返回 `sender_not_supported`，不声称全平台兼容。

- 按已保存完整 UMO 中的平台实例 ID 精确调用 `Context.get_platform_inst()`；实例 ID 可以是 `demo_qq_01` 等任意配置值，不使用平台类型名代替。
- 通过真实 `Context.send_message()`、`MessageSession`、`MessageChain` 和 aiocqhttp `send_by_session()` 路由；群成员隔离会话按宿主规则处理，不自行统一截取或改写 UMO。
- 普通群聊会话必须是纯 ASCII 数字 group_id；成员隔离会话必须是 AstrBot aiocqhttp 入站构造的 `sender_id_group_id`，即恰好一个下划线且两段均为完整 ASCII 数字。私聊必须是纯 ASCII 数字，不含下划线或冒号。空前缀、非数字字段、多余下划线、混入冒号等无法确认的格式在调用宿主前拒绝，不通过“取最后一段”把畸形输入变成另一目标。
- text 使用 `Plain`；Markdown 作为普通文本源码发送，不宣称原生富文本；image 只接受有效 PNG bytes（签名、Pillow 校验、8 MiB 上限），用 `Image.fromBytes`/base64 内存传递，不创建公开 URL、不读文件路径、不请求网络。
- 未找到实例、非 aiocqhttp、非法 UMO/目标/载荷在外部调用前返回 FAILED；已进入 `Context.send_message` 后的异常或无法确定结果返回 UNKNOWN；`CancelledError` 继续传播；不自动重试。
- 成功表示真实宿主路由方法正常完成并调用了支持的 aiocqhttp 发送路径，不保证平台已读、绝对送达或平台 API 回执成功。异常正文/平台响应/凭据不落库、不打印 UMO/正文/PNG。
- 插件入口已装配该发送器并提供 Dashboard 鉴权的手动测试接口；启动本身不发送。聊天命令使用事件会话白名单单独授权；页面已提供启停；受鉴权启停和调度接口不对匿名调用者开放。
- 适配层验证使用真实 AstrBot v4.29.1 源码、真实 Context/aiocqhttp 路由/消息转换，最终机器人网络边界替换为隔离假机器人；未连接真实平台。

## 投递核心与后台集成

投递核心由后台鉴权接口调用，插件入口注入 aiocqhttp 适配层；启动不触发发送。调用方提供已保存任务 ID、执行标识和配置版本；组合、输出方式、UMO、正文和图片均从已保存任务和现有预览生成，不能由调用方传入 URL、正文、UMO 或文件路径。

- 空名单在内容获取/渲染前结束，发送器调用零次。
- 一次执行只准备一份内容；文字/Markdown 为一个逻辑消息，图片按组合配置的栏目顺序逐张处理。
- 候选站点不存在、上游失败或栏目条数不足时，先尝试单站满足，全部不满足再按栏目拼合；拼合后仍缺栏目时向任务白名单发送安全文字异常提示。组合不存在或整次图片无法生成时记录失败；部分栏目未出图时其余栏目照常发送，未出图槽位记为 `skipped` 并带 `section_image_failed`。
- 单站优先阶段某个候选不满足整份任务时，仍可能作为拼合来源提供它能满足的栏目；同一栏目不会跨站拼条数。
- 执行记录的来源模式按实际取数版本和不同来源站点数判定：探测结果携带取数时的站点 revision，返回前与发送前逐站复核；同一站点供多个栏目仍记 `single`，只有不同站点参与才记 `multi`。内部存储/预览故障直接中止且零发送，只有真正没有任何可用内容时才发送异常提示；栏目取数过程中的存储异常保留为 503，不降级成缺栏。预览返回、图片渲染前后和临发送的来源复核都使用一次多站 revision 查询，避免逐个读取的时间间隙。
- 服务的并发/等待准入在读取任务和组合之前执行；满额明确拒绝，不把积压移到读锁之后。执行总数不超过并发+等待上限的上界。
- 发送前先落库目标和页的 `sending` 状态；记录写入后、外部调用前再执行最终配置/生命周期校验，之后不再写入。最终校验复用一次任务配置快照，任务版本、白名单与全部来源候选 revision 必须来自同一次读取；手动确认的有序候选版本在取数前变化会返回 409 `confirmation_stale`。候选站点确实不存在才按无候选处理，存储读取失败中止投递且零发送。外部发送不在数据库事务或存储锁内。
- 只有发送器明确 `success` 才记成功。明确 `failed` 记失败；普通异常、超时和取消保守记 `unknown`。
- 某目标出现失败/unknown 后停止该目标剩余页；其他目标继续。成功、失败、unknown、跳过分别记录，不把部分成功汇总成全部成功。
- 每次发送前重新核对任务、组合和目标；内容投递还核对选中站点的 revision 与启用状态。配置变化后停止尚未开始的投递，不加入新目标，不替换内容。已进入外部调用的结果按实际/unknown 记录。
- 发送成功后写库失败不能变成安全重试；重复执行标识只返回已有状态，不自动重试、不自动恢复、不重启补发。超时返回已有记录前也校验任务归属，其他任务的记录不会被返回或修改。
- 正常 success、no_targets 及没有错误的页/目标保持 `error_code=NULL`；非法发送器错误文本统一归一化为受控内部码。每个执行记录带创建者 owner token；取消/超时/关闭时只有实际创建该记录的工作者能将其标记为 incomplete，重复查询者、创建竞争失败者和其他任务不得修改原执行。
- 执行记录保留任务/组合/站点快照 revision、输出格式、内容哈希、时间、目标和栏目图槽位，以及创建者 owner token；不保存完整新闻正文或 PNG。对外投影字段为 `image_index`（第几张栏目图）和 `image_count`（共几张），数据库表名仍为 `delivery_pages`。删除任务不级联删除历史投递记录。
- 关闭/取消及重开数据库时：尚未进入发送的 `pending` 页/目标终态为 `skipped`（原因 `never_started`）；已落库为 `sending`、可能已进入外部调用的页/目标才归 `unknown`；已知成功/失败保持原状态，执行按页汇总为 stopped/unknown/partial/failed。目标有成功页但剩余页 skipped 时目标为 partial，完全未投递才是 skipped。不补发。

默认上限：最多 20 个目标、6 个栏目图槽位（`max_images`；渲染侧单个任务最多 5 个栏目）、2 个并发执行、4 个等待执行。内容准备预算为 60 秒，包含排队和候选站点内容准备；剩余时间按尚未尝试的候选站点数量分配，只有一个候选时可以使用全部剩余时间。发送阶段另有 30 秒预算，单次发送器调用最多 15 秒；两阶段之外另有少量收尾余量。等待数为 0 表示不排队，但空闲执行槽位仍可使用；执行槽位全满时立即返回容量错误。执行槽位必须 ≥1、等待数必须 ≥0；内容准备、发送阶段和单次发送器超时必须为正的有限数值，拒绝 NaN、Infinity 和数值溢出，非法配置明确拒绝。服务层还会拒绝超过任务/图片既有上限的配置。

## 失败策略

以下行为在代码中固定，没有可配置开关：

- 获取失败或条数不足：该站点不满足任务，按候选顺序尝试下一站；所有候选都不满足时向非空白名单发送文字异常提示。内容失败与提示投递结果分别记录。
- 图片生成失败：全部栏目失败时结束该次执行并记为失败，不发送文字代替；部分栏目未出图时其余栏目照常发送，未出图槽位记 `skipped` / `section_image_failed`。当前没有自动降级或按设置跳过。
- 今日新闻未更新：预览保留上游内容日期并提示旧内容，不冒充今日；投递不做重试或截止时间等待，按已获取结果发送或记录失败。
- 发送结果未知：明确记为 `unknown`，不盲目自动重发。
- 成功目标/页不因其他目标失败而重复发送。

## 数据与升级

站点、内容组合和推送任务保存在同一个数据库 `<ASTRBOT_ROOT>/data/plugin_data/astrbot_plugin_60sapi_hub/sites.sqlite3`；目录由宿主 `StarTools.get_data_dir()` 获取。schema 版本为 16，包含 12 张业务表：`sites`、`content_profiles`、`content_profile_items`、`push_tasks`、`push_task_umos`、`push_task_sites`、`push_schedule_state`、`push_schedule_claims`、`push_schedule_skips`、`delivery_executions`、`delivery_targets` 和 `delivery_pages`。首次建库创建当前结构；受支持的旧 v1～v15 数据库通过同一事务补齐或迁移至 `user_version=16`，迁移取得 SQLite 写锁后重新读取版本，避免并发打开时重复执行迁移。失败回滚，保留旧站点、凭据、组合、任务、白名单及历史。未带来源类型的站点迁移为公开；已带来源类型的记录保持原值，包括旧版迁移留下的自建类型。

任务、投递记录与站点/组合共用同一个 `SiteStore` 连接、锁和事务，不另建 JSON 配置或复制到 `_conf_schema.json`。更新/删除任务按 expected_revision，冲突不覆盖；任务内部方案随任务管理，站点引用受保护。写入失败回滚，取消后下一次正常操作不受影响。

运行依赖 `aiosqlite`、`httpx`、`Pillow` 和 `croniter>=6.2.4,<7` 声明在 [requirements.txt](../requirements.txt)，不依赖宿主碰巧安装的版本，也不安装 AstrBot 本体。内容快照仍只在进程内缓存；任务配置、UMO、执行/发送状态和调度历史均已持久化。

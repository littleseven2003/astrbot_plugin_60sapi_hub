# 架构设计

当前已实现最小插件入口、站点存储和后台站点管理（视图与 Web API），其余业务模块仍为设计约定，在实现相应功能时按需建立。

## 数据流

```mermaid
flowchart LR
    A[后台 / 聊天查询 / 定时任务] --> B[异步获取与缓存]
    B --> C[按接口解析 JSON]
    C --> D[统一内容快照]
    D --> E[文字和 Markdown]
    D --> F[图片模板与分页]
    E --> G[AstrBot 消息发送]
    F --> G
    G --> H[逐目标逐页记录]
```

## 模块边界

插件入口负责宿主装配和生命周期。领域模型负责站点、组合、任务、校验和统一内容；适配器负责 endpoint 字段解析；应用服务负责获取、缓存、预览、调度和投递；渲染负责文字/图片；存储负责迁移和状态；宿主集成负责 Web API、消息及渲染接口。

这些是职责边界，不要求提前创建同名空目录。单个文件足够时不人为拆成多个包。

当前站点管理链路：

- `core/site_api.py`：站点管理用例的业务层，负责请求体到 `SiteCreate`/`SiteUpdate` 的映射、成功响应和校验/未找到/冲突/存储不可用的错误映射；不依赖宿主请求对象。
- `site_web.py`：宿主适配层，读取 Dashboard 请求、检查登录用户和插件启用状态，调用业务层并返回 `astrbot.api.web` 响应。
- `views/sites/`：无构建链的中文 HTML/CSS/JS 页面，通过宿主注入的 bridge 调用 API；凭据只提交、不回显。
- `main.py`：创建站点服务和上述组件，注册路由并维护打开/停用生命周期。

AstrBot 4.29.1 的视图 bridge 只有 `apiGet` 和 `apiPost`，因此更新和删除使用 POST 子路径：`GET/POST /<插件名>/sites`、`GET /<插件名>/sites/<id>`、`POST /<插件名>/sites/<id>/update`、`POST /<插件名>/sites/<id>/delete`。Dashboard 负责扩展路由鉴权；处理器仍检查用户名，并在插件未启用时拒绝读写。错误响应只返回稳定的公开消息和字段/版本信息，不返回堆栈、数据库路径或凭据。

## 实现默认选择

- 异步 Python 3.12；AstrBot 基线 v4.29.1，详见开发手册的兼容性基线。
- 使用一个异步 HTTP 客户端，明确依赖约束。
- 站点配置由 `core/sites.py`（校验与站点服务）和 `core/site_store.py`（SQLite/aiosqlite）实现；后台管理由 `core/site_api.py`、`site_web.py` 和 `views/sites/` 实现；组合、任务、发送记录等实体尚未实现。
- SQLite 存复杂业务实体与发送记录，位置在宿主插件数据目录。
- 少量全局设置使用 AstrBot 配置 schema；业务实体只有一个持久化真源。
- 后台使用宿主插件视图及 bridge，当前站点页采用简单 HTML/CSS/JS，不引入 CDN、外部字体或独立服务器。
- 图片接入经验证可用的宿主渲染能力，默认准备文字降级策略。
- 单实例确定性调度，不依赖大模型任务工具。

## 生命周期

启动：验证 → 数据迁移 → 客户端/宿主集成 → 恢复未来计划。
配置更新：验证并事务保存 → 更新受影响计划。失败不留下半配置。
停用/重载：停止新执行 → 取消并等待旧任务 → 释放网络/渲染资源 → 关闭存储。

当前站点存储在插件 `initialize()` 中打开并完成首次建库，在 `terminate()` 中关闭；打开失败会关闭已创建的连接。站点 Web API 在 `__init__` 中注册，初始化完成前置为未启用；停用时先置为未启用再关闭存储。这样停用后仍可能留在宿主注册表中的旧处理器不能继续读写，重载时新实例以相同路由和方法替换旧处理器。真实宿主已验证停用返回 503、启用/重载后数据保留且没有重复可写处理器。网络获取、渲染和调度尚未接入。

4.29.1 的停用/重载会调用插件 `terminate()`（插件类自身定义 `__del__` 时优先）并解绑处理器；同路由同方法的 Web API 会替换。新增注册项仍须按目标版本源码和实测逐项核验。发送前重新检查任务状态和白名单，已移除目标不得继续接收剩余页。

## 缓存与快照

请求缓存键包含站点、接口、规范化参数和认证/配置版本，避免跨站点串数据。相同请求合并，限制并发。

同次输出共享不可变快照；图片缓存额外包含模板版本、主题和分页参数。清理有容量/保留期，不能删除在途文件。

## 错误与恢复

区分网络超时、HTTP/业务错误、非法 JSON、字段变化、旧数据、渲染错误、平台不可用、投递结果未知。部分栏目失败不等于整份成功。

执行键：任务 ID + 计划时间 UTC；发送记录细分目标 UMO + 页号。成功页不重发。

外部发送与本地写库无法组成原子事务。发送超时或发送后写库前崩溃时标记 unknown，默认不自动重发，避免假承诺 exactly-once。

重启默认恢复未来计划，不集中补发离线任务。日报迟到重试有截止时间，沿用原执行键。

## 接口适配

每个 endpoint 定义 ID、中文名称、相对路径、参数校验、JSON 结构及缓存建议。只请求选中的接口；不把所有返回值当 data.news。

文档存在、夹具通过和真实站点通过是三个不同状态。未适配接口不开放选择。新接口须补充正常/空数据/错误类型夹具与图文输出检查。

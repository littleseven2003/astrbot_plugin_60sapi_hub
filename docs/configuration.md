# 配置说明

当前为设计说明，界面与导入功能尚未实现。实际可用配置将在功能发布时更新。

## API 站点

配置名称、基础地址、启用状态、可选 Bearer 凭据、超时。基础地址约定不含 /v2，可包含反向代理前缀；例如 https://api.example.com/news。

后台应提示误填 /v2，避免重复拼接；保留反代前缀。仅允许 HTTP(S)，不在基础地址中包含用户名密码、查询串或 fragment。

管理员可配置明确的内网/Docker 站点。endpoint 使用受控相对路径，普通聊天不能指定任意 URL；跨源重定向不得转发凭据。凭据在返回结果与日志中脱敏。

## 内容组合

一个组合选择一个站点和至少一项接口。每项设置排序、参数、条数；空条数表示全部上游条目，正整数表示最多展示多少条。

输出支持文字、Markdown、图片。图片可按栏目拆分或合并排版，超长必须分页。同次文字与图片采用同一快照，不能重新抓取导致内容不一致。

缺失字段保持为空，不伪造热度、来源、摘要或发布时间。

## 推送任务

设置名称、内容组合、白名单、输出策略、计划和时区。

- 每日：HH:mm。
- 每周：时间和星期，界面使用明确的周一至周日。
- 间隔：持续时间及持久化的下一执行点，重载不重置为立即发送。
- Cron：五段表达式；具体方言和夏令时处理随采用的调度库公布。
- 默认时区 Asia/Shanghai；记录 UTC，界面显示配置时区。
- 默认停用，空名单允许保存但不能启用发送。

## 推送白名单

每项一个完整 UMO，格式为：`平台实例ID:消息类型:会话ID`。

| 类型 | 虚构示例 |
|---|---|
| 群聊 | demo_bot:GroupMessage:10001 |
| 私聊 | demo_bot:FriendMessage:20001 |

在对应会话发送 /sid，复制 UMO，不复制 UID。平台实例 ID 使用实际值，不固定写 qq 或 telegram。

允许群聊、私聊混合；只去首尾空白和精确去重，不改大小写或截断会话内容。裸群号缺少出站平台上下文，不能猜测目标。

开启群成员隔离时，需核验群级发送标识；不能把成员隔离会话未经验证地视为整个群。

每任务名单独立。插件名单表示主动推送接收者，与 AstrBot 入站访问白名单用途不同，不自动导入或修改全局名单。

## 失败策略

- 部分栏目失败：发送可用栏目或跳过整次，并留下记录。
- 图片生成失败：按设置跳过或降级文字。
- 今日新闻未更新：跳过，或在截止时间前重试。
- 发送结果未知：明确标记，不盲目自动重发。
- 成功目标/页不因其他目标失败而重复发送。

## 数据与升级

站点、组合、任务使用稳定 ID 和配置 revision；删除有引用的对象应阻止。并发编辑冲突不能静默覆盖。

存储包含 schema_version、内容快照、执行与投递状态。更新前备份，迁移失败保留可恢复数据。代码目录不存生产配置/数据库。
